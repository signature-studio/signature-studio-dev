## 3. ecx の置き直し (受入条件 2) の実測

測定 (`X87_PROBE=1 python3 x87_fn_diff.py`、各 200 行または 4,000 行):

## 6. #4924: 広い範囲 (ecx 基底) の書込みを非自明性に数える

判定器の変更 (`x87_fn_native.c`・`x87_fn_entry_wasm.mjs`・`x87_fn_diff.py`): ecx = `0x10700000` の行に限り、image 内の `[0x10700000, 0x11000000)` の変化 (語数と FNV ハッシュ) を数える。 呼出し規約のスタック (`0x10EFE000..0x10F00100`) は数えない。 native と wasm の値が違う行は FAIL (`wide_bad`)。 判定の変更は両方向: 非自明性に数える行が増えた (判定の条件が増えた。 緩んだ側)。 不一致の FAIL を追加した (厳しくなった側)。 ゲート 7 本の結果は変わらない (`wide` が `-`)。

| 試験 | exit | 実測時間 | 結果 |
|---|---:|---:|---|
| `python3 x87_fn_diff.py` (ゲート 7 本) | 0 (PASS) | 20.65 s | 既存 7 本は全て PASS。 広い範囲の変化 0 行・不一致 0 行 |
| `X87_PROBE=1 python3 x87_fn_diff.py` | 1 (想定どおり非自明性 FAIL) | 79.64 s | 3 本とも広い範囲の変化 0 行・不一致 0 行 |

3 本の実測 (X87_PROBE・ecx = `0x10700000`):

- `0x10003fe0` (200 行): 戻り値 `eax=0` が 200 行すべて。 `d=0` (x87 が空)。 wide 変化 0 行。 関数は早期に戻り、`[ecx+0x80174]` (lift 上の書込み先) の経路に入らない。
- `0x100051f0` (200 行): `eax=10c20ce8` の固定値。 wide 変化 0 行。
- `0x1000a95a` (4000 行): `eax` は 0/1 の 2 値。 wide 変化 0 行 (窓を読むだけ)。

結論: 3 本とも、この入力の範囲では ecx 基底の広い範囲に書込みが観測されない。 非自明性の判定に数えられる変化が無いため、`TARGETS` には入れない (受入条件 3 は未達)。 前付録 §2 の「書込み先 `[ecx+0x80174]`」は lift 上の書込み箇所であり、この入力では経路に入らない。 入力の設計 (乱数の窓の値で分岐が変わる) を見直すまでは、判定の根拠を作れない。

未解決: 3 本を判定に通す入力設計 (分岐を通る窓の値・引数の型) は子 issue に回す。 PR 本文の未解決表を参照。
