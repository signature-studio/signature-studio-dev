- 測定 commit: 本付録を含む PR の commit (コードを変えた最後の commit。 下の §4)。 入力は fl-win64 の `block22434_PE.bin` と seed 5423。

## 1. 結論

- 受入条件 1 (辿るポインタの位置): **窓の外**。 lift 出力 (`f_100085a0`) で、ポインタは `[ecx+0x520cc8]` (ecx = 窓の基底)、読む値は `[P + 4*(a0 + 34*[ecx+0x18]) + 0x18]`。 窓 (0x540 B) の中の番地 `[ecx+0x18]` は添字だけに使う。 ポインタそのものは窓の中ではない。
- 受入条件 2 (有効な番地を置く入力で native が segfault せず終わる): 有効な番地は **窓の中ではなく窓の外の 1 語 `ecx+0x520cc8`** に置いた (§2 のとおり、窓の中には置けない)。 **既定 harness は rc -11 のまま**。 複製 (その 1 語に image 内の番地を書く) で **rc 0** (native・wasm とも 2000 行を完走)。
- 受入条件 3 (native と wasm の全行一致): **2000 / 2000 行で全項目一致** (eax・st0・st0d・d・mem・stk・wide)。 不一致 0 件。
- ゲート `TARGETS` には入れていない。 理由: 判定器の非自明性 (OBJ 窓が変わること・広い範囲が変わること) を満たさない (§3)。 既定 harness に窓外の書込み経路が無いため、ゲートに入れるには harness の変更が要る。 これは判定の設計 (#4924) に関わるので、本付録では測定専用に止める。

## 2. 辿るポインタの位置 (受入条件 1)

| 項目 | 値 | lift 出力 |
|---|---|---|
| 関数 | `0x100085a0` | `work/lift_text/ott_lifted.c` `f_100085a0` (19198 行付近) |
| ポインタの読み | `mov eax, [ecx + 0x520cc8]` (`100085b1`) | `R[0] = LD32(R[1] + 0x520cc8)` |
| ポインタの位置 | `ecx + 0x520cc8` (窓の基底から 0x520cc8 B。 窓 0x540 B の外) | 同上 |
| 読む値 | `float [eax + edx*4 + 0x18]` (`100085b7`)。 `edx = a0 + 34*[ecx+0x18]` (`100085a5`〜`100085ae`) | `LDF32(R[0] + R[2]*4 + 0x18)` |
| 窓の中の番地 | `[ecx+0x18]` (添字 = 窓の 0x18 の語。 ポインタではない) | `R[0] = LD32(R[1] + 0x18)` |

- ecx = `0x10700000` (ゲートの窓 `ECX_HI`) のとき、ポインタの位置は `0x10C20CC8`。 既定の `ecx = OBJ (0x10F80000)` では `0x114A0CC8` (16MB の窓 0x11000000 より上)。
- image の長さは `0x6D000` で、オフセット `0x520cc8` は image の長さより大きい。 よって、どの ecx (image 内の番地) を置いても、ポインタの位置は image の外になる。 image の中身だけからは、この読みを有効な番地で満たせない。 外側の 1 語を書く必要がある。

## 3. 測定 (受入条件 2・3)

測定: `python3 lift_text.py && python3 probe_85a0_5423.py` (`work/85a0_5423/`、seed 5423、2000 行)。

| 試験 | rc | 結果 |
|---|---:|---|
| ベースライン (既定 harness・窓の外の語なし) | -11 (SIGSEGV) | 既存の rc -11 を再現 (`REPORT_APPENDIX_4147.md` §3 と同じ) |
| 複製 (`ecx+0x520cc8` に `P` を書く。 `P = IMG_BASE + [0x1000, 0x60000) の 4 B 刻み`。 `a1 = P`、`a0` と `[ecx+0x18]` は 0..15 の添字) | native 0 / wasm 0 | 行数 2000 / 2000。 **全項目一致 2000 / 2000** |

- 一致が自明でない確認: `eax` の種類 1978 個 (`P` が行ごとに変わり、読む値が行ごとに変わる)。 `ST(0)` の float32 の種類 719 個。 `d` は 1 (= 読んだ float 1 個が残る) 全行。 `eax` は全行が image 内の番地を指す (`P + 4*k + 0x18` 相当)。
- 複製の書込み位置: `native_ptr.c` は窓の初期化 (`OBJ_WIN` バイト) の後・`pre` の保存の前に `*(win + 0x520cc8) = a[1]` を置く。 wasm の `entry_ptr.mjs` も同じ位置 (`wideInit` の復元の直後) に置く。 書いた語は、窓の変化 (`mem`・`wide`) の数に入らない。
- 広い範囲 (`wide`) の変化: native 0 / 2000 行 (FNV 初期値 `0000:811c9dc5` 以外の行なし)。 この関数は image 内の広い範囲に書かない。
