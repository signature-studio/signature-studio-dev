- 受入条件 (残り leaf x87 関数 36 本の突合) は **満たせなかった**。 lift 済みで x87 を含み、call・間接分岐・未対応命令を含まない関数は、本 run の走査で 42 本 (既存 2 本を含む)。 そのうち **構造 (eax・x87 深さ・行数) が全行一致して突合が成立したのは 5 本** (既存 2 本 + main (#4146) の 2 本 + 本 PR の 1 本 `10005d20`)。

## 3. 方法の変更 (本 run)

- 本 PR は main (`e0ee551a2`) の `x87_fn_diff.py`・`x87_fn_native.c` を採用した (#4146 の版: TARGETS は 4 本 (既存 2 本 + `1000b6c1`・`1000b936`)、非自明性の判定は `effect` (OBJ 窓かスタックが変わった行))。 競合は `TARGETS` 周辺と `x87_fn_native.c` の定義部分だけで、どちらも main 側を残した。
- 本 PR の追加は `10005d20` の 1 本 (`gen: 'mixed'`、a0 は一様な float32 (±100)、a1..a5 は 0..15 の整数、200 行 (`N_PER_MIXED`))。 既存 4 本の入力列 (seed 2989・4000 行) は変えていない。
- `1000b3a2`・`10001290` は、本 PR の `mixed` 生成で TARGETS に入れると、main の判定 `effect` が 0 / 200 となって FAIL した (OBJ 窓もスタックも書かず、ST(0) だけを返すため)。 判定規則は変えず、この 2 本は範囲から外した (§5 の『構造は一致・非自明性なし』)。
- native のバッファを 32MiB から 64MiB に広げた (`IBUF_SZ`・`OBUF_SZ`)。 40 本 × 200 行の入力と出力が 32MiB に収まらないため (main 側の版にも同じ定義がある)。
- 試験ランナーが異常終了したとき native は exit 0 で抜けて出力が欠ける (本 run で確認: `1000c084` の 2 行目以降が出ず、`rc=0`)。 そのため、行数の突合 (`件数 native / wasm / 期待`) が、欠損の検出の役割を果たした。 ランナーの exit 規約は変えていない (この欠陥は §5 で未解決として扱う)。
