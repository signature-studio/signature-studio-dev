## 12. 0x10012484 の呼出し元と 0x10012529 の入力範囲 (#6039・受入条件 3 の残り)

- 入力: `block22434_PE.bin` (sha256 先頭 `84b64c43`・REPORT と一致)。`objdump -d -M intel` の全逆アセンブル (実行日: 本 run)。
- 0x10012484 の直接呼出しは 0x10012461 の 1 箇所だけ。 0x10012461 の呼出し元は 0x10012415 (`[esp+8]` を受ける大文字化関数) 経由で、0x10012415 の呼出し元は 0x10010924 の 1 箇所だけ (`call` の直接参照のみ。 PE 内に関数ポインタや `jmp` 経由の到達は無い: データ内の絶対アドレスを検索して 0 件)。
- 0x10010924 が渡す値は `movsx eax,bl` の **符号付き 1 バイト** (範囲 -128〜127)。 0x10012415 の `[esp+8]` にそのまま入り、0x10012484 の `[ebp+8]` になる。
- 0x10012484 の分岐 (実測・全 256 値を照合):
  1. `[0x10068150]` (Locale) が 0 なら ASCII 大文字化 (0x61〜0x7a だけ -0x20) で戻る。 `[0x10068150]` は PE 内に書込み命令が無いので、実行時値は host 側が決める (§9.1 と同じ扱い)。
  2. Locale が非 0 の経路では `cmp ebx,0x100` で 0x100 未満なら `[0x10027178]` (= 1) の経路に入り、`[0x10027184]` の ctype 表 (`0x1002718e`) を符号付き添字で引く (`and eax,2`)。 添字が負のとき、表の外 (`0x1002708e`〜) を読むが、ここは 0 埋めと ctype 表の一部で、読み出しは可能。
  3. 符号付き 1 バイトの範囲では、2 バイト経路 (0x100124e2 の `sar eax,8`・`test [edx+ecx*2+1],0x80`) に到達する値は **0 件**。 すなわち 0x10012529 の `cch=2` の経路は、この呼出し経路からは到達しない (`cch=1` のみ)。
- 結果 (Locale 非 0 かつ `[0x10027178]`=1 の経路。 符号付き 1 バイト -128〜127 の全 256 値): `cch=1` で 0x10012529 に入るのは 42 値 (`0x61`〜`0x7a` の 26 値と、0x80 以上の 16 値)。 残りの 214 値は表の判定で素通し (ret)。 Locale が 0 の経路は 0x10012529 に入らない。
- 0x10012529 は `[ebp-4]` (4 バイト) を dest、cchDest=3。 cch=1 なので書込みは 1 バイト以内。 SIGSEGV しない入力範囲は「符号付き 1 バイト全体」で成立する。
- 0x10010924 を含む親関数 (0x100107f9〜) の呼出し元と、その `[ebp+0xc]` の由来は未追跡 (本節は 0x10012484 の入口までの範囲)。

- 訂正 (§13): 本節の「cch=1 で 0x10012529 に入るのは 42 値」は、`0x100107f9` の文字種ゲートを通す前の全 256 値に表を当てた数字。 ゲートを通る値に絞ると 26 値 (§13)。

## 13. 0x100107f9 の文字種ゲート通過後の入力範囲 (#6039・受入条件 3 の残り)

- 入力: `block22434_PE.bin` (sha256 先頭 `84b64c43`・REPORT と一致)。 `objdump -d -M intel` の逆アセンブル。 `0x10010800`〜`0x10010924` は先頭から個別に読み直した (線形走査では途中でずれる)。 ctype 表 (`0x1002718e`) は PE の `.data` から Python で直接読んで判定を再計算した。
- 呼出し: `0x10010924` (`movsx eax,bl` → `call 0x10012415`) は `0x100107f9` の内部。 `0x100107f9` は strtol 型の数値パーサ (`[ebp+0x10]`=基数)。 唯一の呼出し元は `0x100107e2`→`0x100107f0` 経由の `0x1000d9e0` で、基数 10 (`push 0xa`) を渡す。 よって 1 バイトずつではなく **文字列全体を走査し、英字の文字ごとに `0x10012415` (大文字化) を呼ぶ**。 英字の位置の文字だけが 0x10012484 に入る。
- `0x100107f9` のループ (`0x100108ce`〜`0x1001095d`): 文字を 1 つずつ読み、`[tbl+2u] & 4` (数字) なら `u-0x30` を取り、そうでなければ `word[tbl+2u] & 0x103` が非 0 のときだけ `call 0x10012415` (= 0x10012484 の入口) に渡す。 `0x10010924` の戻り値は `sub ecx,0x37` 後に `cmp ecx,[ebp+0x10]` (基数 10) で判定し、基数以上なら打ち切る (`jae 0x1001096a`)。
- **ゲートを通る符号なし 1 バイト u は 52 値**: `41`〜`5a` (A-Z の 26 値) と `61`〜`7a` (a-z の 26 値)。
- 52 値のうち `0x10012484` の表判定 (`[tbl+2v]&2`・v=符号付き) で cch=1 の経路 (0x10012529) に入るのは **26 値 = `61`〜`7a` (a-z)**。 残りの 26 値 (`41`〜`5a`・A-Z) は判定で素通し (ret)。
- 0x10012529 は cch=1 のみ。 dest は `[ebp-4]` 4 バイト・cchDest=3 で、cch=1 なら書込みは 1 バイト以内。
- 以上により、`0x1000d9e0` の文字列入力に対する 0x10012529 の入力範囲は **小文字 a-z の 1 バイト (0x61〜0x7a)** に限られる。 ただし親関数の入力の範囲 (`0x100107f9` の `[ebp+8]` 由来) は未追跡。
- 注意: `[0x10027178]`=1 (PE 初期値 1・書込み命令 0) と `[0x10068150]` (Locale) 非 0 を前提とする。 Locale が 0 の経路 (ASCII) は 0x10012529 に入らない (§12 の 1 のとおり)。 Locale の実値は host 側が決め、PE 内に書込みが無い (§9.1 と同じ扱い)。
