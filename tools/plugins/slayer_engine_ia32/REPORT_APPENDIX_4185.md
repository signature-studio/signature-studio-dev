# REPORT_APPENDIX_4185 — `0x10009eb5` の ST(0) NaN の原因 (PLG-G2-51)

既知類型との関係: `ott_x87.h` の制限 (4) (スタック over/underflow を模型化しない)。 `docs/DEFECTS.md` の既存 ID へは当てていない。 方式は `docs/DECISIONS.md` D28。

- 親: #4064 (PLG-G2-40)。 本付録は #4064 付録 §5 の「`frndint` 後の NaN」の追跡先 #4185 の測定。
- 測定 commit: `573088a23` (測定時点の main の HEAD。 コードは変えていない。 本 PR はこの付録・DOC_MAP・#4064 付録の注記だけを変える)。
- 入力: 素材 fl-win64 の `block22434_PE.bin`・乱数 seed 2989 (`x87_fn_diff.py` の既定の生成)。 `lift_text.py` の被覆は 85.37%・未被覆 10,682 B (#4064 §4 と一致)。
- 起動・GUI に関わらない (製品 KPI は対象外)。

## 1. 結論

- 前提の訂正: #4064 付録と #4185 の本文は「`frndint` 後の NaN 生成」としていた。 **誤り**。 NaN は `frndint` が作らない。 `fn_10009eb5` の先頭は `fld st(0)` で、呼出し時の x87 スタックが空。 空スタックの読みを native (実機) は default NaN (-qNaN `ffc0_0000_0000_0000`) にし、`frndint` はそれをそのまま通す。
- wasm の模型は空のレジスタを 0 で読む。 これは `ott_x87.h` の制限 (4) (underflow を模型化しない) の範囲で、#4146 (PLG-G2-49) の決定 (`REPORT_APPENDIX_2989.md` §8・`REPORT_APPENDIX_4088.md` §3.1) と同じ類型。
- 模型は直さない。 理由: 空レジスタの読みを default NaN にすると、harness の全対象 (既存ゲートの 2 本を含む) の入口状態が変わる。 #4146 (CLOSED) は underflow を模型の範囲外として扱い、wasm 側を変えない方針 (`REPORT_APPENDIX_2989.md` §8・`REPORT_APPENDIX_4088.md` §3.1)。 ゲートの件数は変えずに済むが (§2.1)、この方針の再判断は PM が行う。

## 2. 測定

### 2.1 仮説の検証 (一時的な変更・コミットしない)

glue (`x87_fn_glue.c` の `ott_call32x`) で、呼出し前のレジスタ 8 本を `x87_indef()` にした一時変更で再測定した:

- `0x10009eb5` の ST(0): `nan-num` 4,000 → `eq` 4,000。 **ST(0) の NaN の差はこれで消えた**。
- `0x10009eb5` の eax 不一致は 4,000 のまま (IE・SF の差。 これは模型が flag を持たない限界で、本付録の範囲外)。
- ゲート 5 本の件数は変わらず (3,890・3,405・4,000・4,000・200)。 ネガコン `--nega` (15,495 → 15,494) と `--nega-lower` (4,000 / 4,000 不一致) は検出。

変更は取り消した (`git checkout` で glue を元に戻し、worktree は clean)。
