# #5999 (CI-249): function_f552a0 の呼出し第 1 引数を機械語 `[rbx]` (= *%arg1) に戻す (opt-in・既定 OFF)

親: #5995。判定の根拠は #5995 のコメント 6228635866 (6 件の対応表・原因 A/B)。

## 1. 結論

- 修正 pass `ldfix/fix_f552a0.py` を追加した。機械語どおり、`0xf552a0` のループ内 5 箇所 (f5531d を含む) と脱出後 1 箇所の `call` (計 6 件) の第 1 引数を、呼出しの直前に `inttoptr %arg1` と `load i64` で挿入した値にする。`rcx.0`/`rcx.1` の loop-carry は外す。
- 前版 (r1) の誤り: 機械語の `[rbx]` を `%arg1` と読んでいた。`rbx` = `%arg1` で、`[rbx]` はその指す先の 8 バイト (`*arg1`) の load である。r1 の IR 上の確認と測定は、この誤った引数に対するもので、修正後の根拠にならない (§3)。
- **既定 OFF** (`M11_FIX_F552A0=1` で有効)。既定 ON にすると e2e の期待値ゲートが赤のままになるため。
- 受入条件 1・2 は、修正 pass の合成 IR での構文検証まで満たした。実 IR (`work-m11`) での再生成と再測定は未実施 (§3)。受入条件 3 (引数を照合する判定器) は未着手 (§5)。

## 2. 修正内容と機械語の根拠

機械語 (`block00031_PE.bin`・capstone 実測。#5995 のコメント 6228635866 の表):

| 機械語 | 内容 |
|---|---|

- 呼出し 6 件の第 1 引数: `%rcx.0.reload` ×4 と `%21` ×1 と `%rcx.1.reload` ×1 → いずれも、直前に挿入した `%fx5999o<N>` (= `load i64, ptr (inttoptr %arg1)`)。
- `%rcx.0.reg2mem` / `%rcx.1.reg2mem` の alloca・store・reload を削除。
- 検査 (pass 内 assert): 適用後に `rcx.0`/`rcx.1` の参照が 0 件、挿入 load が 6 件、二重適用は止まる。
- 検証: 同形の合成 IR (`function_f552a0` の 6 呼出しを模した最小 IR) に pass を適用し、`clang 18` (`-c -x ir`) が通ることを確認。実 IR の変換と再測定は未実施。
