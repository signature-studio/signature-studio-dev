# #5999 (CI-249): function_f552a0 の呼出し第 1 引数を機械語 `[rbx]` (= %arg1) に戻す (opt-in・既定 OFF)

親: #5995。判定の根拠は #5995 のコメント 6228635866 (6 件の対応表・原因 A/B)。

## 1. 結論

- 修正 pass `ldfix/fix_f552a0.py` を追加した。機械語どおり、`0xf552a0` のループ内 5 箇所と脱出後 1 箇所の `call` の第 1 引数を `%arg1` にし、`rcx.0`/`rcx.1` の loop-carry を外す。
- **既定 OFF** (`M11_FIX_F552A0=1` で有効)。既定 ON で出すと e2e の期待値ゲートが赤のままになるため。opt-in の e2e 測定でも数値は変わらなかった (§3)。
- 受入条件 2 (ループ先頭で毎回 `%arg1` から読む) と 1 (`%21` → `%arg1`) は IR 上で満たした。受入条件 3 (引数を照合する判定器) は未着手 (§5)。

## 2. 修正内容と機械語の根拠

機械語 (`block00031_PE.bin`・capstone 実測):

| `f552b6` / `f552ce` / `f552e8` / `f55318` / `f5532b` / `f5534b` / `f5536d` | 各 `call 0x12df530` の直前に `mov rcx, qword ptr [rbx]` |

- 呼出し 6 件の第 1 引数: `%rcx.0.reload` ×4 と `%21` ×1 と `%rcx.1.reload` ×1 → すべて `%arg1`。
- `%rcx.0.reg2mem` / `%rcx.1.reg2mem` の alloca・store・reload を削除。
- 検査: 適用後の `function_f552a0` に `rcx.0`/`rcx.1` の参照が 0 件。二重適用は assert で止まる。
