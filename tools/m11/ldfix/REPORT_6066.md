## 3. 方式の決定

**決定: B 先頭への単純な load 挿入 (`fix_f3c_use` の現行の `at` 選び) は採らない。** 理由は 2 つ。

1. **値使用とアドレス使用の区別が要る。** 置換対象は、`%argN` を「アドレス」として deref する使用だけではない。10626e0 の 38 行は `%argN` を格納先アドレスとして使うが、786d50 / 787380 の 27・36 行は `ptrtoint` で値を取り、41a670 の 28 行は値として比較する。`fix_f3c_use` は使用の種類を区別せず `load [%argN]` の値で全部置換する。値使用を load の値に置換すると、機械語が使っていた引数値を別の値にすり替える。よってこの 4 組の使用は、現行の置換規則の対象外とする。
2. **支配されない使用の原因は未確認。** 101d180 の 32 行 (`store i64 %arg3`) は、B (101d469) の直前の crit-edge ブロック (101d180.dec_label_pc_101d469_crit_edge) に近いが、どの経路で B を迂回するかは測っていない。`residual_3195` は機械語の生の使用数 (`keep=0`) を数えるだけで、IR 側の使用位置との対応は本 REPORT では確かめていない。

**代替方式 (未実装・候補のみ):** 「B 以外からの経路で値を使う形」は、支配する deref ブロック (12f9730 の 159、41a670 の 33 のように一部の使用は既に支配される) ごとに置換し、残りは現状のまま残す形が候補。ただし §2 の値使用 (ptrtoint・比較・格納先) は、どの方式でも load では表せないため、置換の対象から外す規則を先に決める必要がある。この規則の決定は本 PR の範囲外。
