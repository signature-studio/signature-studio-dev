# REPORT_2555 — 同類型 (スピル引数の 1 段 deref 脱落) の候補 16 箇所 + 0x7888f0 の IR 側判定 (#2555 / CI-103)

既知類型との関係: **DEFECTS.md D4** (引数 reg 経由の disp=0 deref 脱落 → 値がアドレスのまま使われる)。
#2502 (REPORT_2502.md) と同じ機構。新規類型ではない。

## 0. 結論

- 機械語の走査候補 **14 関数 / 16 deref 箇所** (`scan_spill_deref_2502.py`・変更なし。REPORT_2502 §4 と一致) を、1 箇所ずつ機械語窓と IR の call 引数で判定した。
  - **誤り 12 箇所 (10 関数)**: 機械語は `*argK` を呼出し先へ渡すのに、IR は `%argK` (アドレス) や別の式を渡している。
  - **偽陽性 3 箇所 (3 関数)**: 走査が拾った deref の後で、同じ引数レジスタが spill 枠から再ロードされ、call 時点では `argK` そのもの。IR の `%argK` と一致する (誤りではない)。
  - **判定不能 1 箇所 (1 関数)**: 機械語の呼出しに対応する IR の呼出しが無い (0x439f90)。
- 走査が取りこぼした **0x7888f0** (rbx への複写経由) は、誤り 1 箇所。
- 同類型の誤りの合計は **13 箇所 / 11 関数** (VA 一覧は §2)。
- 受入 ② (誤りの IR 修復と `ldfix_e2e.sh` の実測) と ③ (取りこぼし検出の定義) は本 PR では未達。子 issue へ移した (§6)。

## 1. 数え方と再現

- 対象: `tools/m11/work/boot_final3.ll` (ldfix 前の base IR) と PE `block00031_PE.bin` (fl-win64 26.1.7.5653)。
- **deref 箇所**: (関数 VA, deref 命令 VA, call 命令 VA) の 3 つ組。関数数は関数 VA の distinct 数。
- 判定基準:
  - 誤り: 機械語が呼出し先の引数 p に `*argK` (arg K の指す先の 8 バイト値) を渡すのに、IR の p 番目の引数が `%argK` (または trunc/zext/ptrtoint の包み) か、arg K 由来の load を含まない式。
  - 偽陽性: D (`mov reg,[reg]`) の後、C (call) の前に、同じ引数レジスタが `[rsp+X]` (spill 枠) から再ロードされ、call 時点の値が `argK` そのもの。
  - 判定不能: 呼出しに対応する IR の呼出しが無い、または対応が一意に取れない。
- 再現 (測定 commit `b186f7d4`):

- 最終判定は、2 の一次分類を入力に、3 の窓を人手で読んで付けた (判定根拠は §2 の表と `tools/m11/ldfix/work/judge_{A,B,C}.json`。gitignore 対象のため commit しない)。

## 3. 偽陽性の原因 (走査の定義の穴)

- 偽陽性 3 件は全て、D (`mov rcx,[rcx]`) の直後に `mov rcx,[rsp+X]` (spill 枠の arg 再ロード) が入り、call 時点の rcx が arg 自身になる形。
- 走査 (`scan_spill_deref_2502.py`) の C 判定は「D の後 6 命令以内に call」だけを見ていて、D と call の間の再ロードを見ない。
- 修正の方向 (③ で定義する): D と call の間で同じ引数レジスタへ再度書く命令 (再ロード・`mov`・`lea` 等) があれば、C を満たさない。本 PR では走査を変えない (REPORT_2502 の数字を保つため)。

## 4. 比較・消費側の取りこぼし (別件・同類型の定義に含まれる)

#2555 本文の定義は「比較・消費の位置で逆参照が落ちる」も含む。走査は call 引数だけを見るため、次の 2 件は候補に出ない:

- 0x413c00: 機械語 0x413c55〜0x413c58 は `cmp rcx(=*arg1), rax`。IR 119763 行は `icmp eq %arg1, %arg2` (`*arg1` の load 無し)。
- 0x414c70: 機械語 0x414cbf〜0x414cc2 は `cmp rcx(=*arg1), rax`。IR 121042 行は `icmp eq %arg1, %arg2`。
- 0x413340: 呼出し 1 番目の誤り (表 #1) に加え、3 番目の引数が機械語の r8 (arg2 の spill) と一致しない (IR の `%14`)。

## 5. 一次分類 (機械) と最終判定の比較

`verify_deref_sites_2555.py` の一次分類 (ADDR 5 / OTHER 9 / MISMATCH 2 / SCAN_MISS 1) は、最終判定と次のとおり一致しない:

- ADDR 5 件: 最終判定は偽陽性 3 (0x413c00・0x414c70・0x44f240)、誤り 2 (0x6074b0・0x4505d6)。
- OTHER 9 件: 全て誤り (0x413340・0x44f040・0x44fb40・0x450420・0x450560 の 0x450583・0x4505c9・0x4506e0・0x47b4a0・0x47cf10)。
- MISMATCH 2 件: 0x439f90 (判定不能) と 0xc40770 (誤り)。
- SCAN_MISS 1 件: 0x7888f0 (誤り)。

一次分類は「ADDR / OTHER / MISMATCH」の振り分けにしか使えない。最終判定は窓の人手読みによる。

- ネガティブコントロール (陽性対照): `fix_450560.py` を `boot_final3.ll` に適用した IR (`tools/m11/ldfix/work/nc_fixed_2555.ll`、作業ファイル) で一次分類を再実行すると、0x450560 の 3 箇所が `OTHER/ADDR` から **LOAD (arg 由来の load)** に変わった (0x450580 `%v1`・0x4505c6 `%v1c`・0x4505d6 `%v2c`)。修復が効いた箇所を機械的に検出できる。
- 偽陽性 3 件の NC: 再ロード命令の VA (0x413c5d・0x414cc7・0x44f25b) を機械語窓で確認。C 判定に再ロードの除外を入れる変更は未実装 (③)。
