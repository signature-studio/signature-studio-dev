### 9.2 結論 (受入条件 1・2 の更新)

1. **観測の副作用を除いた比較 (受入条件 1)**: 読出し前に範囲を確認する版 (`M11_DEST_GUARD=1`) では、範囲外の読出しが 0 件のまま unit 158 は ok に戻る (870/24・OFF と同じ)。ガード 0/1 は同じ読出し対象を読むため、読出し行為の有無だけで ON の unit 158 の trap が変わる。**ON の unit 158 の確定結果 (既定 build の ON 版としての ok/trap) は、読出しを伴う計測の範囲では「trap」、範囲確認を入れた計測では「ok」**であり、読出しと観測の副作用を分離した確定値は得られていない。
2. **結論 (受入条件 2・意味的差かビルド差か観測副作用か)**: **未決のまま**。確定した点は次の 2 つ。(a) 「読出しが範囲外を踏んで trap を起こす」は否定された (st=3 が 0 件)。(b) 値差 (unit 158 j=12: OFF は `*dest`=NULL、ON は長さ 1 の文字列) はガード 0/1 の両方で残るため、ON で dest の値が変わる点は観測手段によらず再現する。ただし、この値が本物の挙動か、ON の C 転記版が別の値を書いた結果かは未切り分け。
3. **未切り分け点**: 読出しの有無で trap が変わる機構は未特定。読出し後の値の利用経路の確認 (IR と ON の C 転記版の突き合わせ) が要るが、本節では実施していない。この作業は子 issue の範囲とする (§9.3)。
4. **決定性 (受入条件 3)**: OFF 2 回で記録 227 件が完全一致。ガード ON も同一 build の 2 回で記録 227 件が完全一致 (指紋 `ac2d2efb758d4bb1`)。
