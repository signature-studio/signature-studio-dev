## 2. ネガティブコントロール (受入条件 3): 未達

比較が「動作差を作れる」ことを示す既知変更を 2 種類試した (旧 HEAD `8f7a2303` で実施)。どちらも差を検出できなかった。

| 既知変更 | 変更内容 | survey ラベル差 | 判定 |
|---|---|--:|---|
| (a) `M11_OV_414AD0=1` | #683 で退行が既知の UStrSetLength 版に切替 | 0 unit | 感度を示せない |
| (b) 413060 本体を意図的に壊す | `Q(dest) = p` → `Q(dest) = p + 0x40` (一時変更・戻し済) | 0 unit | 感度を示せない |

- (b) は 413060 が書く文字列ポインタを壊す変更で、survey の ok/trap/miss 判定は変わらない。survey の unit 判定は「trap するか」しか見ないため、ポインタの値の差は観測できない。
- 補助として heap 全体の sha256 を比べたが、同一 build の連続実行でも値が変わった (OFF で 2 通り: `48005711…` と `919c9e7e…`)。ヒープには非決定な領域があるため比較手段にならない。この追記は撤回した。

**したがって、現在の survey 指標では 413060 の動作差を検出できる感度が無い。** ネガコンを成立させるには、413060 直後の `dest` の値を観測する手段 (例: 413060 の出力 `Q(dest)` を probe でダンプし OFF/ON で比較) が要る。これは本 run の範囲を超えるため未解決とする (§4)。

受入条件 3 は子 #1149 ([M11-N67]) へ移管済みだが、受入条件の移管は issue スコープの変更で PM の確認が要る。PM が認めない場合は、感度を示すネガコンをこの PR で追加する必要がある。
