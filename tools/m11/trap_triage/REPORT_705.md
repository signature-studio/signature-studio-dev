## 3. 413060 の機械語 (本 run で再確認)

fl-win64 の `extracted/block00031_PE.bin` (ImageBase 0x400000) を capstone で逆アセした結果:

```
413060: push rbp / push rdi / push rsi / push rbx / sub rsp,0x38 / mov rbp,rsp
413074: mov rax, qword ptr [rbx]          ; 旧値 old := [rbx] (分岐より前に無条件で実行)
413077: mov qword ptr [rbp + 0x28], rax   ; old を stack に退避
41307b: test edi, edi / jle 0x4130a4      ; 分岐
...
4130ab: lea rcx, [rbp + 0x28]            ; &old を渡す
4130af: call 0x412d60                    ; 旧文字列を解放
```

(a) 本 run で上記アドレス (413074 / 413077 / 4130ab / 4130af) を確認。`lea` は 0x4130ab、`call` は 0x4130af。
(b) 直接 call/jmp の走査 (前版の値, 本 run では未再実行): rel32 で `0x413060` を指す箇所は 60 件以上。絶対参照 (abs64) は 0 件。survey での unit 別到達は未計数。

IR (`work/boot_final.ll`, `function_413060`) は 413074 のロードを持たず、`store i64 %arg1, ptr %stack_var_-48` → `call @function_412d60(i64 ptrtoint(%stack_var_-48))` となる。つまり `412d60` が読む「旧文字列ポインタ」が dest のアドレスに置き換わっている (D4 形)。
