# PY-58 (#1973): chan 上で +0x794 を書く箇所 (書込み元) の特定 (部分・未達)

親: #1916 (PY-55)。前段: `REPORT_PY55.md`・`REPORT_PY51.md`。既知類型との関係: 該当なし (lift 作業ではない)。

## 結論

- 受入条件 1 (chan 上で `+0x794` を書く箇所を PE 解析箇所つきで特定) は**未達**。chan の `+0x714`・`+0x718`・`+0x739` と同一関数で `+0x794` を書く箇所は確認できなかった。
- 受入条件 2 (`+0x794` 書込み候補を分類し、chan 以外を除外) は**一部達成**。実書込み 16 件を分類した (§1)。chan ではないと判断: 11 件。判断保留: 1 件 (`0x8ed012`)。未確定: 4 件 (`0xffe370`・`0xec60ae`・`0x1306dbf`・`0x130760f`)。
- `REPORT_PY55.md` の訂正: `0x8ed012` は「オブジェクト初期化・chan ではない」としていたが、同じ関数で `+0x714`・`+0x718` を 0 で初期化している。chan を含む親オブジェクト (`[rbp+0x70]`) の初期化と見られるため、chan 系の経路かは判断保留とする。
- `REPORT_PY51.md` との差: `0x100165c` の関数は `+0x79c` を **dword** で 0 にする (`mov dword [rax+0x79c],0`)。PY-51 は `+0x79c` を byte flag として扱っていた。幅の違いは別構造体の可能性を示すが、chan との同定は未確定。

### 1-1. `0x8ed012` の文脈

`0x8ed000` 付近の初期化関数 (`[rbp+0x70]` が対象) で、`+0x758`・`+0x2c`〜`+0x37`・`+0x70`・`+0x74`・`+0x3c`・`+0x44`・`+0x4c`・`+0x18`・`+0x6dc`・`+0x75c`・`+0x10`・`+0x77c`・`+0x20`・`+0x28` を初期化し、その中で `+0x714`・`+0x718` も 0 にする。`+0x794` の書込みは `0x511fe0` の戻り値を格納するもので、`[rbp+0x70]` が chan かどうかは未確定。
