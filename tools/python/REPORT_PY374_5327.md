# tools/python REPORT: screen テキスト行 addTextLine の未同定点の PE 確定 (#5327, 親 #4741)

> 前段: `tools/python/REPORT_PY170.md` (addTextLine の呼出し鎖・`0xd82c20` の code 別分岐)・`REPORT_PY121_2985.md` (screen の 5 関数・`scr == 0` の経路)・`REPORT_PY135.md` (blank と `0xd7e330` の呼出し)。
> 既知類型との関係: 該当なし (lift ではなく PE の直接逆アセンブル。docs/DEFECTS.md の類型は対象外)。

## 結論

- 受入条件の 3 関数 `0xd7d460`・`0x4f2990`・`0x41c6e0` の意味を PE の根拠 (VA) 付きで確定した。
- **`0xd7d460` の戻り値は呼出し元が使わない**。呼出し元 `addTextLine` (0xd7acaf) は戻り値を読まず、`0xd82c20` に渡すのは PyArg の解析結果 `ebx` である (REPORT_PY170 §1 の「`0xd7d460` の戻り値は使われない」を確認)。
- `0xd7d460` の役割は「テキスト行 1 件を screen 状態に登録する」処理である。行配列 `[scr+0x1c4]` の末尾に 1 要素を追加し、テキストの計測値から矩形の補正値を作り、`isUnBlank`・`activeCounter` を更新してから `0xd7e330` を呼ぶ。
- 保留にした点は §4 に列挙した。`0xd7e330` の本体・`0x668670` の内部・`scr+0x1dc` の書込み元は、本 run では確定していない。mock・C は変更しない (値の確定が要る)。

## 手段

- 展開: 素材 `[WIN64]` (fl-win64) を `tar --zstd -xf <素材> -C <展開先>` で展開 (全体展開 11 秒)。`FL_WIN64_DIR=<展開先>`・`extracted/block00031_PE.bin`。
- 逆アセンブル: `cd tools/python && FL_WIN64_DIR=<展開先> python3 analysis/flapi/pe_disasm.py <VA> <命令数>`。本文の命令列はこのコマンドで読んだもの。
- RIP 相対の先は手計算 (次命令のアドレス + disp32)。検算: `0xd7d55d + 0x1b3 = 0xd7d710`、`0xd7d575 + 0x19b = 0xd7d710`、`0xd7d5db + 0x13d = 0xd7d718`。読んだ定数: `0xd7d710` = 0.4999999701976776 (double)、`0xd7d718` = 2.0。
- 引数の位置: `0xd7d460` の `rbp` は entry の `rsp - 0xd8`。5 番目以降の stack 引数は `[rbp+0x100]`・`[rbp+0x108]`・`[rbp+0x110]`・`[rbp+0x118]` に入る (entry + 0x28 / 0x30 / 0x38 / 0x40 を `rbp = entry - 0xd8` で換算)。

## 1. `0x4f2990` = 4 個の int を構造体へ詰める (確定)

逆アセンブル (0x4f2990〜0x4f29a4):

```
mov rax, rcx
mov [rax], edx          ; S.x = a1
mov [rax+4], r8d        ; S.y = a2
mov [rax+8], r9d        ; S.z = a3
mov ecx, [rsp+0x28]
mov [rax+0xc], ecx      ; S.w = a4 (5 番目の引数)
ret                     ; rax = S へのポインタ
```

- 引数: `rcx` = 出力先 `S`、`edx`・`r8d`・`r9d`・stack 5 番目 = `a1`〜`a4`。戻り値は `rax` (= `S`)。
- 構造体は 16 byte (dword 4 個)。`S.x` = a1、`S.y` = a2、`S.z` = a3、`S.w` = a4 の順。
- 呼出し例: `addTextLine` (0xd7ac78) は `a1 = [0x9c]`・`a2 = [0x98]`・`a3 = [0x94]`・`a4 = [0x90]` を渡す。これは書式 `siiii` の int 4 個と対応する (REPORT_PY170 の out の順)。
- 補助関数 (確定): `0x4204d0` = `S.z − S.x` (幅と読める。`mov eax,[rcx+8]; sub eax,[rcx]`)。`0x4204f0` = `S.w − S.y` (高さと読める)。`0x4204e0` は `S.w ← S.y + edx` (高さの設定)。

## 2. `0x41c6e0` = char* を参照カウント付き文字列へ複写する (確定。型は推定)

逆アセンブル (0x41c6e0〜0x41c76f) の骨格:

- 引数: `rcx` = 出力先の文字列変数のアドレス (`&[rbp+0x78]` の形で呼ばれる)、`rdx` = `char*`。戻り値 `rax` = `rcx` (出力先)。
- `rdx` が NULL、または先頭 byte が 0 のとき: `0x412d60(rcx)` で既存の値を解放して空にする (0x41c704〜0x41c708)。
- それ以外: `0x413660` で長さを得る (strlen 相当、0x41c713)。`0x414ad0(rcx, len)` で長さを設定する (0x41c720)。`0x414850(*rcx)` で データ領域の先頭を得る (NULL なら静的な空バッファ。0x41c72c)。`0x41c360(buf, len+1, src, len)` で複写する (0x41c740)。複写できた長さが 0 以下なら解放する (0x41c75b)。

確定した構造 (`0x414ad0`・`0x414850`・`0x412d60` の読み):

- 文字列の データ領域 `p` について、`[p-8]` = 参照カウント (`cmp dword [rax-8], 1` の形で参照)、`[p-4]` = 長さ (`cmp dword [rax-4], esi`)。Delphi 系の AnsiString と読める (推定。ヘッダ 0x10 byte)。
- 参照カウントは `0x412f30` (AddRef: `lock xadd +1`)・`0x412d60` (Release: `lock xadd -1`、0 になると `0x409440` で解放) で扱う。

呼出しの意味: `addTextLine` は `s` (Python 側の文字列) をこの形で `[rbp+0x78]` に写し、`0xd7d460` の `rdx` に渡す。

## 3. `0xd7d460` の役割 (確定した処理。意味は一部推定)

引数 (entry の位置は §0 の換算):

| 位置 | 内容 | 根拠 |
|---|---|---|
| `rcx` | `obj` (= `scr`。`[rbp+0x30]` に保存) | 0xd7d46d |
| `rdx` | 名前の文字列 (`[rbp+0xe8]`) | 0xd7d483 |
| `r8` | `&S` (4 int 構造体へのポインタ。16 byte を `[rbp+0xb0]` へ複写) | 0xd7d471〜0xd7d481 |
| `r9d` | 第 4 引数の int (`[rbp+0x3c]`。`[rbp+0x90]` へ写して 0xd7d517 で使う) | 0xd7d474 |
| 5 番目 `[rbp+0x100]` | `-1` のとき既定値 = `obj+0x14c` (`[rbp+0x100]`) | 0xd7d4c0〜0xd7d4d3 |
| 6 番目 `[rbp+0x108]` | `-1` のとき既定値 = `obj+0x148` (`[rbp+0x108]`) | 0xd7d4a7〜0xd7d4ba |
| 7 番目 `[rbp+0x110]` | 0 (オフセット。0xd7d59e で `cmp 0` の分岐) | 0xd7d59e |
| 8 番目 `[rbp+0x118]` | 0 (`0xd7e330` の第 3 引数 `r8d` に渡る) | 0xd7d6d5 |

`addTextLine` の呼出し (0xd7acaf) は 5 番目・6 番目に `-1`・7 番目・8 番目に `0` を渡す。つまり既定値で呼ばれている。

処理の順序 (逆アセンブル順):

1. **名前の参照**: `0x412f30(name)` で AddRef。`0x413480(&[rbp+0x68], name)` で参照を複製。`0x415610(&[rbp+0x54], type)` で記録の初期化 (呼出し先の本体は未同定)。
2. **既定値の補完**: 5 番目・6 番目が `-1` なら `obj+0x14c`・`obj+0x148` の dword で置き換える。
3. **テキストの計測**: `0x668670(rcx = [obj+0x1a8], rdx = name, r8 = &[rbp+0x48], r9 = &[rbp+0x40], 5 番目 = 0, 6 番目 = byte [rip+0x209])` を呼ぶ (0xd7d51d〜0xd7d54b)。出力は 2 つの double (`[rbp+0x48]`・`[rbp+0x40]`)。
4. **整数化**: `[rbp+0x48] + 0.4999999702` を `0x40c660` で整数化して `[rbp+0x94]` (幅候補)。`[rbp+0x40] + 0.4999999702` を整数化して `[rbp+0x98]` (高さ候補)。`0x40c660` = `cvtsd2si` (確定。最近接偶数)。`[rbp+0x98]` は本関数内で読まれていない (0xd7d57a 以降の読みを確認)。
5. **行の矩形の補正**:
   - `[obj+0x1e4]` (int) を float 化して `[rbp+0xa4]` に入れる (0xd7d58e〜0xd7d596)。
   - 7 番目 (`[rbp+0x110]`) が負のときは 0xd7d5a7〜0xd7d5f0 の枝。`[rbp+0x94] > 0x4204d0(&S)` (S の幅) のときだけ、`[obj+0x1e8]` で割って 2.0 を掛け、`0x40c660` で整数化して `[rbp+0x110]` を更新する。
   - その後 `[rbp+0x94] > 0x4204d0(&S)` のとき `[rbp+0xa0] = float([obj+0x1e8])`、そうでなければ `[rbp+0xa0] = 0` (0xd7d604〜0xd7d622)。
   - `[rbp+0xa8] = float([rbp+0x110])` (0xd7d62c〜0xd7d634)。`[rbp+0xac]`・`[rbp+0xad]` = 1 (0xd7d63c〜0xd7d643)。
6. **行配列への追加**: `obj+0x1c4` (動的配列。要素数は `[配列ポインタ-8]`) の末尾に 1 要素を追加する。`0x417fc0(&[obj+0x1c4], type, 1, n+1)` で長さを `n+1` にする (0xd7d65e〜0xd7d67a)。追加した要素は `base + (n)*0x5c` (0x17 dword = 92 byte。0xd7d6a2 の `imul rax, rax, 0x17`・`lea rcx, [rcx+rax*4]`)。
7. **要素の複写**: `0x416750(elem, &[rbp+0x54], type)` で記録 (`[rbp+0x54]`) を要素へ複写する (0xd7d6aa〜0xd7d6b5)。
8. **screen 状態の更新**:
   - `[obj+0x1cc] ← [obj+0x1dc]` (activeCounter の復元。0xd7d6be〜0xd7d6c4)。
   - `[obj+0x1d1] ← 1` (isUnBlank = 真。0xd7d6ca)。`REPORT_PY121_2985` の isUnBlank の読み (`byte [scr+0x1d1]`) と一致。
9. **後処理**: `0xd7e330(obj, &[rbp+0x54], [rbp+0x118])` (0xd7d6dc)。その後 `0x415c30`・`0x412d60(&[rbp+0xe8])` で一時の参照を解放して終わる (0xd7d6e6〜0xd7d6f9)。
10. **戻り値**: 呼出し元 (0xd7acaf) は戻り値を読まない (§0)。

**行 id の仮説**: REPORT_PY170 の未解決 2 の「`0xd7d460` の戻り値は行 id か」は、呼出し元が戻り値を使わないため成り立たない。行の位置は、7 の要素追加で決まる配列上の位置 (`n`) であり、関数の戻り値としては渡されない。
