## PY-5414 (#6015): D (cell `0x15F7190`) の格納元・生成候補と `+0x168` の書込み元

親: #2642 (PY-82)・子 #6015 (PY-5414)。前提ゲート `0xd5af58` の `[[P]+0x168]` の D を同定する (受入 1・2)。全件は `analysis/flapi/py69_d_origin.py` で再現する。

- 測定 commit: 本 PR の最後のコード commit (`git log -1 -- tools/python/analysis/flapi/py69_d_origin.py`)。
- 前提 `0x1262bad`〜`0x1262bbe` の読み (PE 実測): `mov rax,[rip+0x380544]` (= P `0x15E30F8`) → `mov rax,[rax]` → `cmp dword [rax+0x168],0` → `jle`。つまり **D = [[P]]**。P (`.data`) の PE 値は slot `C = 0x15F7190` (`.bss`) で、`[C]` が D のポインタ (実行時に決まる)。

### 結論 (確定した点・未確定の点)

| 項目 | 結果 | 状態 |
|---|---|---|
| D の経路 | P (`0x15E30F8`、`.data`・PE 値 `C`) → C (`0x15F7190`、`.bss` の slot) → `[C]` = D のポインタ → `[D+0x168]` | 確定 (前提ゲートの逆アセンブル) |
| C への RIP 直接の store | **0 件**。`lea` 参照も 0 件。RIP 相対の load は 170 件 (`py69_d_origin.py` (1)) | 確定 (全 `.text` 走査) |
| P の参照 | P を RIP 相対で参照する命令 362 件 (`py69_d_origin.py` の出力)。C の参照 (load 170 件) とは別集計 (合算しない) | 確定 (走査) |
| C への**クリア**候補 | `0x620c2d` `mov rax,[P]`・`0x620c34` `mov qword [rax],0` (`0x620c00` の初期化関数内)。C の中身 (= D のポインタ) を 0 にする | 確定 (逆アセンブル) |
| C への**生成**候補 | `0x620e00` `call 0x867710` → `0x620e05` `mov rcx,[P]` (= C) → `0x620e0c` `mov qword [rcx],rax`。`rax` は `call 0x867710` の戻り値 | 候補。`0x867710` の戻り値の型と中身は未読 |
| `[reg+0x168]` への書込み | 全 `.text` で 245 件 (`py69_d_origin.py` (3)。幅別に byte 13・dword 63・qword 169)。`[reg+0x168]` を読むだけの命令 (`add reg, dword [..+0x168]` 等の 8 件) は含めない。ただし同基底の D 由来の判定は 0 件 | **未確認**。判定が 2 段チェーン (`[P]`→`[rax]`) を追えないため、0 件を根拠にできない |

- 判定: `+0x168` は D のフィールドだが、その書込み元 (`dword [D+0x168]` を書く関数) は**未同定**。`py69_d_origin.py` の (3) は「直前 40 命令内で同じレジスタに P を読んだ」型しか見ないため、前提ゲートと同じ 2 段チェーンの D 由来の書込みは拾えていない。
- 推測で書込み元を付けない。次の一手は `0x867710` の戻り値 (C に入る D の型) を読むこと。

### 限界・範囲外

- 走査は RIP 相対参照の全 `.text` 走査と、直前 N 命令の同一レジスタ判定に限る。関数をまたぐ・ヒープ経由の D は拾わない。
- `0x867710` の戻り値の型、`0x620c00` 初期化関数の呼出し元、`+0x168` の書込み元 245 件の各関数の所属は未確認。
- `0x15F7190` の内容 (= D の実体) は実行時にしか決まらない (bss)。

### 次の提案 (前 run の時点。下の「解決」で置換)

- `0x620e0c` を含む関数の入口を特定し、`0x867710` の戻り値 (D の型) を読む。
- 245 件の `+0x168` 書込みのうち、同関数内で `[P]` を読むものを優先して D 由来かを判定する (`analysis/flapi/py69_d_origin.py` の (3) を拡張)。

### 解決 (run 2・#6015)

逆アセンブルで次を確定した (絶対 VA、ImageBase `0x400000`、`block00031_PE.bin`)。

| 項目 | 結果 | 根拠 (PE 箇所) |
|---|---|---|
| D の生成 | `0x620e00` が `call 0x867710` → `0x620e0c` `mov [C],rax`。`0x620cd0` 始まり `0x620ea6` で ret する関数内 | `0x620dfb`〜`0x620e0c` |
| `0x867710` の戻り値 | `[rbp+0x270]` に入れた値を返す。その値は `0x620dfb` の `dl=1` を受けて `0x867744` で呼ぶ `0x410320` の戻り値 (`call [rax-0x30]` の結果) で置き換わる。**型は未確定** (仮想呼出し先と `[0x855878]` の実体は未読)。関数内に `[reg+0x168]` への書込みは無い | `0x867734`〜`0x86774c`・`0x410320`・`0x620dfb`〜`0x620e0c` |
| `+0x168` の増加関数 | `0x8683b0`: `add dword [rbx+0x168],1` (1 になったとき `0x8688a0` を呼ぶ) | `0x8683b8` |
| `+0x168` の減少関数 | `0x868400`: `sub dword [rbx+0x168],1` (0 になったとき `0x8688a0` を呼ぶ) | `0x868408` |
| 増減関数の呼出し地点 | 9 件 (inc 3・dec 6)。`rcx` は D (`[C]` 直接 3 件 `0x8636cb`・`0x8639af`・`0x863b1f`、`[[P]]` 6 件) | `py69_d_origin.py` (4) |

- 判定: D に対する `+0x168` の増減は、`0x8683b0` (inc) と `0x868400` (dec) の呼出し 9 件で行われる (呼出し元で `rcx`=D を確認)。`+0x168` が参照カウントであることは推定 (1 と 0 の境界で `0x8688a0` を呼ぶ構造から) で、未確定。
- 未確認: 245 件の直接書込み (`mov/add/sub [reg+0x168]`) のうち、この 2 関数の外にあるものが D を指すかは確認していない。
- 手動確認: `0x863b1f` (`mov rcx,[P'] → call 0x868400`)、`0x8775a1`、`0x880aaf`、`0x880aeb` を逆アセンブルで照合 (`rcx` が D であることを確認)。
- 限界: `rcx` の由来は「直前 6 命令内に `mov rcx,[C]` または `mov rax,[P]`+`mov rcx,[rax]`」の型で判定 (`py69_d_origin.py` (4))。関数をまたぐ D の受け渡しは拾わない。`0x8683b0`/`0x868400` 以外の `[reg+0x168]` 直接書込み (245 件のうち 2 関数外) が D を指すかは未確認。

### 追跡 (run 3・#6015)

逆アセンブルで次を読んだ (`block00031_PE.bin`、絶対 VA)。

| 項目 | 結果 | 根拠 (PE 箇所) |
|---|---|---|
| D を作る引数 | `0x620df4` `mov rcx,[0x855878]` → 値 `0x855940`。この PE 値を `0x867710` の `rcx` (this) に渡す | `0x620df4`・`0x620e00` |
| `0x867710` の呼出し元 | 1 箇所 (`0x620e00`) | 全 `.text` の `call 0x867710` 走査 |
| `0x867710` の戻り値 | `[rbp+0x270]` (= 初期 `rcx`) を返す。`dl≠0` のとき `0x867744` で `0x410320` を呼び、その戻り値で置換してから返す | `0x867734`〜`0x867751`・`0x867b1b`〜`0x867b37` |
| `0x410320` | `dl≥0` のとき `call [rax-0x30]` (rax = 引数)。戻り値は仮想呼出し先に依存 | `0x410320`〜`0x410335` |
| `0x410360` | `call [rbx-0x50]` (vtable)。`0x867b24` 経由で呼ばれる | `0x410360`〜`0x41037d` |
| `0x867710` 本体の `+0x168` 書込み | 無し (本体の書込み先は `this` の他のオフセット) | `0x867710`〜`0x867b86` を通読 |

- 判定: `0x620e00` の `this` は `0x855940` (静的オブジェクト)。`dl=1` の経路では `0x867710` の戻り値は `0x410320` の `call [rax-0x30]` の結果で、`this` そのものではない。よって D (= `[C]`) の値は `0x855940` とは限らず、**D の型・実体は未確定** (推測で型を付けない)。
- 注: `0x855940` の先頭 qword は `0x50cd90` (.text)。vptr かどうかは未確認。
- 直接書込み 245 件の由来: `py69_d_origin.py` と同型の線形追跡 (関数内・call で由来を消す) では 245 件すべて「由来不明」で、D 由来と判定できた書込みは 0 件。ただし追跡は関数の引数や call の戻り値を追えず、**0 件は「該当なし」の証拠にならない**。未確認。
- 再現: `analysis/flapi/py69_d_origin.py` の (5) (`provenance()`) が同じ線形追跡を行う。出力は 由来 `?` 245 件・由来 D 0 件 (run 3 のコミット時点、約 3 分 45 秒、rc=0)。上の表の PE 箇所は逆アセンブラ出力を人手で読んだもの。

### 未解決 (run 3 時点)

- D (`[0x855878]` の値 `0x855940`) の型と、そのメンバ `+0x168` の**直接**書込み元。
- 245 件の直接書込みのうち、関数をまたいで D を指すもの。
- `+0x168` の増減が参照カウントであること (推定のまま)。


### 追跡 (run 4・#6015): D の型の手がかり

測定: `analysis/flapi/py69_d_type_probe.py` (`FL_WIN64_DIR=<展開先> python3 analysis/flapi/py69_d_type_probe.py`)。コード commit は本 PR の最後のもの。実測 rc=0、real 1m8.059s (load 0.98 付近)。

| 項目 | 結果 | 根拠 (PE 箇所) |
|---|---|---|
| `[0x855878]` の値 | `0x855940`。`.text` 内を指す連続 qword が 17 個の関数ポインタ表の先頭 (vtable 形状) | `py69_d_type_probe.py` (1) |
| `0x855878` を RIP 相対で読む命令 | 2 件: `0x620df4` (D の生成の引数) と `0x7412af` (未読) | `py69_d_type_probe.py` (2) |
| `0x855940` を RIP 相対で指す命令 | 0 件 (表は `0x855878` の値として間接に使われる) | (2) |
| `dl=1` の仮想呼出し先 `[0x855940-0x30]` | `0x40f960`。`[rbx-0x80]` で `0x409410` を呼び、`0x40fb40` を呼ぶ。`0x40fb40` は `[rsi]=rdi` (this) を格納し、`[rcx-0xc0]`・`[rcx-0x78]` を辿るリスト走査を行う | `0x40f960`〜`0x40f981`・`0x40fb40`〜`0x40fbe0` |
| `0x40f960` の戻り値 | **未確定**。`0x40fb40` の戻り値の取り方を読んでいない | — |

判定:
- 「D が `0x855940` そのもの」とは言えない。`0x855878` の値が vtable 形状の表を指すため、`0x855940` はオブジェクトの vptr か、オブジェクトの実体のどちらかである。どちらかは未確認。
- D の型・実体は未確定。`0x40f960` の戻り値 (= `0x410320` の結果) の型が決まれば D の型の候補が出る。
- `0x7412af` が `0x855878` を読む経路は未読 (D の別の参照元の候補)。

未解決 (run 4 時点):
- D の型・実体 (`0x40f960` の戻り値 → `0x410320` の結果 → `0x867710` の戻り値)。
- 関数をまたぐ D 由来の直接書込み (245 件のうち由来 D の判定)。`py69_d_origin.py` (5) の線形追跡は 0 件で、0 件は該当なしの証拠ではない。
- `+0x168` が参照カウントであること (推定のまま)。
