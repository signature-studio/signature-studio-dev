## 結論 (検査した範囲)

- K (`0x16bacf0`・dword) への書込みは、検査した経路で **0 件**。直接参照 (RIP 相対・絶対 disp32) の全エンコード、領域 `[0x16baaf0, 0x16bad20)` を指す lea 28 件を根にした別名追跡 (深さ 2 の direct call 先まで)、領域のポインタの非スタック格納 (0 件)、領域を指す lea 由来の bulk copy (0 件) のいずれも K に当たらなかった。K を指す lea は 0 件。
- K = 0 の前提は**反証されなかったが、確定はしていない**。残件は子 #3504 [PY-207] へ移送: (a) 宛先の由来が静的に決まらない文字列命令 167 件 (§3)、(b) 戻り値で返る領域ポインタ 7 件の呼出し側 (§2)、(c) K を含む構造体の大きさ (§4)。
- 基底・大きさ: 基底候補は `0x16bacb8` (K の 0x38 手前)。V (`0x16bacec`)・表 T (`0x16bacd8`)・K は、この基底からの相対アクセスには現れず RIP 相対で個別に参照される。K の直後の大域 (`0x16bacfc`〜`0x16bad18`) も RIP 相対の書込みを持つ。単一の構造体としての大きさは静的に確定できない。

## 2. lea 由来の別名追跡 (受入 2)

- 根: 領域 `[0x16baaf0, 0x16bad20)` を指す RIP 相対 lea 28 件 (線形走査。バイト照合でも同じ命令の RIP 先を確認)。K を指す lea は 0 件。領域を指す絶対即値 (`mov r32, imm32`) は 0 件 (バイト列照合)。
- 追跡: 根の直後 400 命令。別名は mov・lea・add/sub 即値で伝播し、明示オペランドの書込みで失効させる。ret で停止。別名が rcx/rdx/r8/r9 で渡る direct call は深さ 2 まで同方式で追う (引数に別名を渡す call 108 件)。
- 結果: 別名経由のメモリアクセスは 38 件。K を覆うものは 0 (読み 0・書込み 0)。領域内への書込みは 10 件。全て 8 バイトの `mov qword ptr [rbx], 0` (`0x4181a4`・`0x412d74`) か `mov qword ptr [rbx], rsi` (`0x413443`) で、`lock` 付きは無い。書込み先は `0x16baaf8`・`0x16bab00`・`0x16bab08`・`0x16bab20` (2 件)・`0x16bac40`・`0x16bac58` (2 件)・`0x16bac60` (2 件) で、いずれも K の手前 0x90 以上の位置。
- 領域のポインタの格納: 別名を格納する `mov [mem], reg` は 26 件。そのうち領域の値を格納するものは 6 件 (命令位置 5 箇所: `0x86a485`・`0x662688`・`0x415c40`・`0x4183df`・`0xba9ad8`) で、いずれも `[rbp + disp]` への格納。所属関数の `.pdata` の UNWIND_INFO の FrameRegister は全て rbp (`FrameRegister=rbp`) で、rbp をフレームポインタとみなし、スタック上の格納とする。非スタック (大域・ヒープ) への格納は 0 件。
- 戻り値: 領域の要素ポインタが `ret` で rax に載る箇所が 7 件 (`ret` `0x41820b` 4 件 (`0x16baaf8`・`0x16bab00`・`0x16bab08`・`0x16bac40`)・`0x412da1` 3 件 (`0x16bab20`・`0x16bac58`・`0x16bac60`))。呼出し側は未追跡で子 #3504 へ。
- 注意: 根ごとの offset の表示には、一巡で大きな負の値になるもの (例 `-17138688`) がある。関数内の算術で別名が誤伝播した疑いがある。K 判定は別名から算出した絶対アドレス (eff) で行うため、誤った別名値は K 判定を誤らせ得る。本検査はこの誤伝播の影響範囲を示していない (K への書込みは 0 件と出たが、誤伝播の影響は未検査)。

## 3. memcpy・rep 文字列の宛先 (受入 2)

- import: 名前付き import 738 件 (`pefile` で import ディレクトリを parse した後に取得)、`jmp [IAT]` の thunk 832 件。名前に `mem` を含む thunk は 4 件 (memset `0x5e1120`・CoTaskMemAlloc `0x469100`・CoTaskMemFree `0x469110`・GlobalMemoryStatus `0x4238d0`)。
- memcpy/memmove/memset の呼出しは 7 件 (全て memset thunk `0x5e1120` 経由: `0x5e456f`・`0x5e47b1`・`0x5e4927`・`0x5e5011`・`0x5e5037`・`0x5e55cc`・`0x5e6a58`)。rcx が領域の別名となる呼出しは 0 件 (bulk=0)。ただし、これら 7 件が別名の追跡窓に入ったかは確認しておらず、bulk 経路の正の対照 (rcx に領域の別名を持つ呼出しの検出) は実行していない。
- 文字列命令 (`rep movs`・`rep stos`) は 250 件 (capstone の mnemonic が `rep` で始まるもの)。宛先 rdi の由来を、直前 300 命令 (文字列命令は除く) の rdi 書込みで分類した:

| rdi の由来 | 件数 |
|---|---|
| `lea rdi, [rip + 領域]` | 0 |
| `lea rdi, [rip + 領域外の大域]` | 1 |
| `lea rdi, [rbp/rsp + ...]` (スタック) | 83 |
| `lea rdi, [reg + ...]` (レジスタ由来) | 37 |
| `mov rdi, ...` | 25 |
| `pop rdi` | 20 |
| `xor` | 1 |
| 直前 300 命令に rdi の書込み無し | 83 |

- 領域を指す lea を宛先とする bulk copy は 0 件。スタック宛ては K に届かない。
- 未確定は 167 件 (`lea rip` 領域外の大域 1 件 + レジスタ由来 37 + mov 25 + pop 20 + 書込み無し 83 + xor 1)。宛先のレジスタ・メモリがどの領域を指すかは静的に決まらない。子 #3504。

## 4. 構造体の基底と大きさ (受入 1)

- 基底候補 `0x16bacb8` (K − 0x38)。根 `0xf83151` が `lea rcx, [rip + 0x737b60]` で基底を作り、`mov r13, [rcx + rax*8]` (rax は 0 か 1) で、8 バイトのポインタを 2 件並べた表を引く。根 `0xf83828` も同じ基底で、8 バイトずつ進む反復で `mov rcx, [rbx]` を読む。
- 基底からの相対アクセスは `+0x00` の読みと配列の添字だけで、`+0x20` (T)・`+0x34` (V)・`+0x38` (K) への基底相対アクセスは 0 件。V・T・K は RIP 相対で個別に参照される。
- 大きさは確定できない。K の直後 (`0x16bacfc`・`0x16bad00`・`0x16bad08`〜`0x16bad18`) にも RIP 相対の書込みがあり、領域は個別の大域の並びに見える。子 #3504。
- 旧版の前段の表 (`[0x16bacd8]`・V・K の関係) は REPORT_PY176 §6 の未解決として残る。
