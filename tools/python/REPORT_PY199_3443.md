# PY-199 (#3443): K (0x16bacf0) への書込み経路の検査 (直接参照・lea 由来の別名・bulk copy)

親: #3403 (PY-195)。前段: `tools/python/REPORT_PY195.md` §5 — ただし当該ファイルは main にも既存ブランチにも無い (#3403 の run は着手コメントだけで成果を push していない)。前段の数値 (K への RIP 相対 store 0 件・bulk copy 0 件) は引き継がず、同じ検査を本 REPORT で再実行した。
関連: `tools/python/REPORT_PY176.md` §3・§6 (V・K・表 T の位置)、PR #3409 (K の RIP 相対書込み 0 件。未マージ)。
既知類型との関係: 該当なし (lift 作業ではない。PE の逆アセンブルによる静的解析)。

## 結論 (検査した範囲)

- K (`0x16bacf0`・dword) への書込みは、検査した経路で **0 件**。直接参照 (RIP 相対・絶対 disp32) の全エンコード、K を指す lea 28 件を根にした別名追跡 (深さ 2 の direct call 先まで)、領域のポインタの非スタック格納 (0 件)、領域を指す lea 由来の bulk copy (0 件) のいずれも K に当たらなかった。
- K = 0 の前提は**反証されなかったが、確定はしていない**。残件は子 #3504 [PY-207] へ移送: (a) 宛先の由来が静的に決まらない文字列命令 167 件 (§3)、(b) 戻り値で返る領域ポインタ 7 件の呼出し側 (§2)、(c) K を含む構造体の大きさ (§4)。
- 基底・大きさ: 基底候補は `0x16bacb8` (K の 0x38 手前)。V (`0x16bacec`)・表 T (`0x16bacd8`)・K は、この基底からの相対アクセスには現れず RIP 相対で個別に参照される。K の直後の大域 (`0x16bacfc`〜`0x16bad18`) も RIP 相対の書込みを持つ。単一の構造体としての大きさは静的に確定できない。

## 0. 対象・前提

- 対象: `block00031_PE.bin` の全 `.text`。線形走査で 5,022,467 命令、再同期 161,366 回 (復号不能バイト・埋込みデータ)。
- 素材: `$ARTIFACTS_DIR/fl-win64.tar.zst` (2,324,302,252 バイト) の実在を `ls` で確認し、`extracted/block00031_PE.bin` (22,227,016 バイト) を repo 外に展開して使用。
- 書込みの判定は capstone の access 情報 (CS_AC_WRITE) で行う。`pe_xref.py` は `mov` 以外の書込み (add・xchg・cmpxchg・lock xadd 等) を load と分類するため使わない。
- 検査ツール: `tools/python/analysis/flapi/pe_k_struct_probe.py` (本 PR)。

## 2. lea 由来の別名追跡 (受入 2)

- 根: 領域 `[0x16baaf0, 0x16bad20)` を指す RIP 相対 lea 28 件 (線形走査。バイト照合でも同じ命令の RIP 先を確認)。領域を指す絶対即値 (`mov r32, imm32`) は 0 件 (バイト列照合)。
- 追跡: 根の直後 400 命令。別名は mov・lea・add/sub 即値で伝播し、明示オペランドの書込みで失効させる。ret で停止。別名が rcx/rdx/r8/r9 で渡る direct call は深さ 2 まで同方式で追う (引数に別名を渡す call 108 件)。
- 結果: 別名経由のメモリアクセスは 38 件。K を覆うものは 0 (読み 0・書込み 0)。領域内への書込みは 10 件で、`0x16baaf8`・`0x16bab00`・`0x16bab08`・`0x16bab20`・`0x16bac40`・`0x16bac58`・`0x16bac60` の 8 バイト格納 (`mov [rbx], 0` / `mov [rbx], rsi`) と、`lock xadd` を含む。いずれも K の手前 0x90 以上の位置。
- 領域のポインタの格納: 別名を格納する `mov [mem], reg` は 26 件で、領域の値は全て rbp/rsp 相対 (スタック) への格納。非スタック (大域・ヒープ) への格納は 0 件。
- 戻り値: 領域の要素ポインタが `ret` で rax に載る箇所が 7 件 (`ret` `0x41820b` 3 件・`0x412da1` 4 件。値 `0x16baaf8`・`0x16bab00`・`0x16bab08`・`0x16bab20`・`0x16bac40`・`0x16bac58`・`0x16bac60`)。呼出し側は未追跡で子 #3504 へ。
- 注意: 根ごとの offset の表示には、一巡で大きな負の値になるもの (例 `-17138688`) がある。関数内の算術で別名が誤伝播した疑いがある。K を覆う判定は絶対アドレスで行うので結論には影響しないが、根ごとの範囲は信用しない。

## 3. bulk copy の宛先 (受入 2)

文字列命令 (rep movs/stos) は線形走査で 250 件。宛先 rdi の由来を、直前 300 命令 (文字列命令は除く) の rdi 書込みで分類した:

| rdi の由来 | 件数 |
|---|---|
| `lea rdi, [rip + 領域]` | 0 |
| `lea rdi, [rip + 領域外の大域]` | 1 |
| `lea rdi, [rbp/rsp + ...]` (スタック) | 83 |
| `lea rdi, [reg + ...]` (レジスタ由来) | 37 |
| `mov rdi, ...` | 25 |
| `pop rdi` | 20 |
| `xor` | 1 |
| 直前 300 命令に rdi の書込み無し | 83 |

- 領域を指す lea を宛先とする bulk copy は 0 件。スタック宛ては K に届かない。
- 未確定は 167 件 (`lea rip` 領域外の大域 1 件 + レジスタ由来 37 + mov 25 + pop 20 + 書込み無し 83 + xor 1)。宛先のレジスタ・メモリがどの領域を指すかは静的に決まらない。子 #3504。
- memcpy/memset 等の呼出し: block00031 の import 参照は pefile の import table に無く (`iat = 0`)、名前で識別できなかった。引数に別名 (rcx) を渡す call 108 件は §2 で列挙した (深さ 2 まで)。

## 4. 構造体の基底と大きさ (受入 1)

- 基底候補 `0x16bacb8` (K − 0x38)。根 `0xf83151` が `lea rcx, [rip + 0x737b60]` で基底を作り、`mov r13, [rcx + rax*8]` (rax は 0 か 1) で、8 バイトのポインタを 2 件並べた表を引く。根 `0xf83828` も同じ基底で、8 バイトずつ進む反復で `mov rcx, [rbx]` を読む。
- 基底からの相対アクセスは `+0x00` の読みと配列の添字だけで、`+0x20` (T)・`+0x34` (V)・`+0x38` (K) への基底相対アクセスは 0 件。V・T・K は RIP 相対で個別に参照される。
- 大きさは確定できない。K の直後 (`0x16bacfc`・`0x16bad00`・`0x16bad08`〜`0x16bad18`) にも RIP 相対の書込みがあり、領域は個別の大域の並びに見える。子 #3504。
- 旧版の前段の表 (`[0x16bacd8]`・V・K の関係) は REPORT_PY176 §6 の未解決として残る。
