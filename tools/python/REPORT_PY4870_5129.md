## 共通の呼び出し形

| 段 | VA | 観測 |

## 関数ごとの意味論

### setPatternName (0xd64f30・fmt `is`)

- 入力: index (int)・name (str)。handler は PyArg で index を `[rbp+0xac]`、name 文字列を `[rbp+0x98]` に受け、`0x41c6e0` で変換した値を ctx (`r9`) で渡す。
- index 範囲検査は **callback 側** (0..999、外は -4 "Index out of range")。handler 側に検査は無い。
- callback 0xd64ea0 → `0x12d0f80(index, name)`。書込み先は静的配列 `rec = 0x193FCE0 + index*0xc0` (`lea rax,[rip+0x66ed51]` の次命令 0x12d0f8f + disp で求めた VA。index×24 を ×8 して 0xc0)。`rec+0` に name を `0x4133f0` で代入 (参照カウント付きの代入・lock xadd で旧値を解放)。
- その後、`[[rip+0x31261e]]` (ポインタ) が非 0 なら `0xe3ef60` を呼ぶ。さらに `byte[rip+0x310026]` が 0 なら `0x1046780(index)` (レコード単位の通知と推定・未確定)、続いて `[global]->+0x7a8` の vtable `+0x1f0` を 2 回 (行範囲の再描画と推定・未確定)。
- 戻り値: 成功 → status 0 → None。gate 偽 → -2 → 例外。index 範囲外 → -4 → 例外。
- 副作用 (確定): `rec+0` (name)。推定: UI 通知。

### setPatternColor (0xd651e0・fmt `ii`)

- 入力: index・value (int32 色)。
- callback 0xd65130 で index 範囲検査 (-4)。色変換は bit 演算で確定: 入力 `v` の byte を低位から b0・b1・b2・b3 とすると、出力は `o = 0xFF<<24 | b0<<16 | b1<<8 | b2` (b3 は捨て、alpha は 0xFF に固定)。式は `eax = (v & 0xff00ff00) + ((v & 0xff00ff)<<16) + ((v & 0xff00ff)>>16) | 0xff000000`。**入力の b0 が赤かどうか (色順) は未確定**。FL 側の色順の根拠が無いため、C 側の実装時に実機値と照合する (未解決の表)。
- `0x12d1470(index, o)`: `rec+8` (dword) に `o`、`rec+0x14` (byte) に `(o & 0xffffff) != [global]` (既定色との比較・名前は未確定)。続けて `0xc2e7a0` を呼ぶ (UI 側の後処理と推定・未確定)。
- 戻り値: 成功 None・gate 偽 -2・範囲外 -4。
- 副作用 (確定): `rec+8`・`rec+0x14`。

### setPatternLength (0xd653a0・fmt `ii`) と incrementPatternLength (0xd65670・fmt `ii`)

- setPatternLength: index 範囲検査は **handler 側** (0xd653fe〜0xd65410。範囲外は dispatch を通らず status -4 を `0xd82c20` に渡す)。value を callback 0xd65300 が `[0,0x200]` に clamp し、`[global ptr] + index*0xc0 + 0x44` (dword) に `clamp(value) * [global]` を書く (`[global]` は 1 ステップあたりの単位数・名前は未確定)。基底は `qword [0x15e2aa0]` (`[rip+0x87d742]` の読出し値) で、`0x193FCE0` と同じかは静的に確定していない (未確定)。式 `rcx + idx*0xc0 + 0x44` は命令列から確定。戻り値: 成功 None、gate 偽 -2、範囲外 -4。範囲外の value は例外にならず clamp される (確定)。
- incrementPatternLength: handler 側で index 範囲検査 (-4)。現在値 `rec+0x44 / [global]` (cdq; idiv) に引数 `delta` (`[rbp+0x98]`) を足し、その結果を 0xd65300 の callback が `[0,0x200]` に clamp して `rec+0x44` に書く。したがって `newSteps = clamp(curSteps + delta, 0, 512)`、`rec+0x44 = newSteps × [global]` (確定)。
- 範囲外 index は handler 側で status -4 (dispatch を通らない)。
- 副作用 (確定): `rec+0x44` (setPatternLength と同じ表・同じ式)。
- 注意: 読みは handler 側で行うため、callback の実行時点より前の値を使う (callback が遅延実行されると差が出る・#3772 と連動)。

### duplicatePatternData (0xd65540・fmt `i`) — 未確定

- 入力: index。handler 側で index 範囲検査 (-4)。callback 0xd654e0 で再度検査し、`0x12ceb60(index)` を呼ぶ。
- 本体 0x12ceb60: `0x12d16a0(index, 1)` でレコードを取得 (無ければ作る)・`rec+0x14` (count) 分のループ・`0x8da350`・`0x1017ad0`・`0x409410(0x18)` の確保・`0x409c80` による 0x18 バイト単位の複写・オフセット加算 (`add [r13], ebx`)・`0x12d8ad0`・`0x12d1760(index, 0)` (rec の再計算・`0x12d1760` の本体は読んだ)・UI 通知の列。
- 「何を何へコピーするか (同じパターン内の複製か、別パターンへの複製か・オフセットの単位)」は、`ebx` と `[r13]` の意味が確定しないため決めていない。推測実装はしない。
