# PY-55 (#1916): chan の +0x794 書込み元と +0x79c 書込み先の同定 (部分)

親: #1871 (PY-51)・#1829 (PY-50)。前段: `REPORT_PY51.md`。既知類型との関係: 該当なし (lift 作業ではない)。

## 結論

- 受入条件 3 (`0xdbdd50` と `0xdbde10` の配列が同一か) は**達成**。両関数とも RIP 相対で同じ絶対アドレス `0x15e2218` (`.data`) を読む。
- 受入条件 1 (`+0x794` の chan 上の書込み元) は**未達**。chan 生成・初期化経路 (`0xdc1440`・`0xdc1060`) に `+0x794` 書込みは無いことを再確認したが、chan 上の書込みは特定できなかった。
- 受入条件 2 (`+0x79c` dword・qword 書込み先の構造体同定) は**未達**。`0xdd2002`・`0xec7bb8`・`0xec6098` の対象構造体は同定していない。
- PY-51 の記述を訂正する: `0xdbdd50` の配列 global を `0x8244b5`、`0xdbde10` を `0x8243c1` としていたが、これは命令内の RIP 相対 disp の表示値であり、絶対アドレスではない。絶対アドレスは両方 `0x15e2218`。

## 測定条件

- 素材: `fl-win64.tar.zst` → `extracted/block00031_PE.bin` (`tar --zstd -xf ... --wildcards '*block00031_PE.bin'`、実測 2.8 秒)。展開先は `tools/python/work/py55/` (gitignore)。
- 測定 commit: `61ca0ecb` (コードを変えた最後の commit。解析スクリプトと本 REPORT)。
- 解析スクリプト: `tools/python/analysis/py55_fieldwrites.py` (新規)。disp32 のバイト列を検索し、ヒット位置の直前 1〜11 バイトから復号して、開始位置が命令境界で disp を含む命令を採用する。
- ヒット数 (実測): `0x79c` 89 件、`0x794` 469 件 (PY-51 の 90・470 とほぼ一致)。
- 既知箇所の検証: `0xdd2002` (`mov qword [rax+0x79c], rcx`)・`0xec7bb8` (`mov dword [rax+0x79c], esi`)・`0xdc1540` (`mov byte [rbx+0x79c], 1`)・`0xf4c976` (`mov byte [rax+0x79c], cl`) は逆アセンブルで PY-51 と一致。

## 注意: スクリプトの偽陽性

本スクリプトは、ヒット位置の前から復号するため、命令の途中から読んだ誤りの命令 (例: `0xdd2003`・`0xec7bb7`・`0xec7bb6`・`0x8ed013`) を出す。出力の VA は、**関数コンテキストで確認した箇所だけ**を採用する。`0x8ed013` は実際は `0x8ed012` の `mov qword [rcx+0x794], rax` (オブジェクトの初期化関数 `0x8ed000` 付近、`+0x10`・`+0x18`・`+0x77c` 等と同じ関数) で、chan 生成経路ではない。

## 1. `+0x794` の書込み候補 (未確定)

`0x794` を書く候補 (スクリプト出力) を、関数の前後文脈で分類した。

| VA | 書込み | 判断 |
|---|---|---|
| `0x8ed012` | `mov qword [rcx+0x794], rax` | オブジェクト初期化 (`0x8ed000` 付近)。chan ではない |
| `0xffe370` | `mov dword [rcx+0x794], edx` | `+0x9c`・`+0x7ac` を扱う関数。chan 文脈は確認できず |
| `0xa27a2c`・`0xa31f63` | `mov dword [rbx+0x794], eax` | `+0xe84`・`+0x530`・`+0x770` を扱う別クラス。chan ではない |
| `0xec60ae` | `mov dword [rax+0x794], ecx` | `[rbp+0x120]` の対象。PY-51 でも未確認 |
| その他 (`0xa25fba`・`0xbd17ee`・`0x11b71ed` 等) | — | 未分類 |

chan 上の `+0x794` 書込み元は、この候補のどれにも確定しなかった。

## 2. `+0x79c` の dword・qword 書込み (未確定)

PY-51 の 3 箇所 (`0xdd2002`・`0xec7bb8`・`0xec6098`) は、前回の判断 (chan 以外の構造体) を維持する。対象構造体の型は未同定。

## 3. 配列 global (確定)

| 関数 | 読出し VA | 絶対アドレス | 用途 |
|---|---|---|---|
| `0xdbdd50` | `0xdbdd5c` `mov rax,[rip+...]` | `0x15e2218` | `0xfe8bb0(arr, edx)` で要素取得 |
| `0xdbde10` | `0xdbde50` `mov rax,[rip+...]` | `0x15e2218` | `0xfe8bb0` で要素取得 |

両関数は同じ配列を使う。`0x15e2218` は `.data` の同一スロット。
