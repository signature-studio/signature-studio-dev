## 結論

- **0x12e3a60 (確定)**: select mode 1 の後処理。track の `+0xd8 == 3` なら `src = +0xe0` を `0x11e84a0` で検査し、`TChanList` (G1) の要素 `id` (`+0x258`) を得て、`[G2+0xa9] ≠ 0` かつ `1 ≤ id ≤ 500` のとき `0x128f9e0(G2, id, 1)` を呼ぶ。`+0xd8 == 1` の枝は `+0xdc` を同じ形で渡す。
- **0x12e7f80 (確定・一部推定)**: track 表 (要素 0x114 B = dword 0x45 個・1〜500) の `+0xd4` (印) と `+0xd6`・`+0x3c` (状態 byte) を書き換える。`+0x49e` (cfg の bool) の意味は未確定。
- **0x666780 の呼出し元 (確定)**: 0xd56770 が `0x12e7f80` を呼んだ後に `0xbd68e0(k=0x26, flag=0)` を呼ぶ。0xd56770 の所属クラスは未確定。
- **未確定**: cfg のクラスと `+0x49e` の意味、`0x128f9e0` の名前、`0x666780` の枠の消費側、0xd56770 の所属 VMT。

## 1. 0x12e7f80 (確定・一部推定)

引数: `rcx` = track 表の base、`edx` = index、`r8b` = 引数 (`ebx` で使う)、`r9d` = 引数 `s` (`sil` に保存)。

- 先頭 (0x12e7fb1〜0x12e7fd2): `k = 1..500` を走査し、`byte [base + k*0x114 + 0xd4] ≠ 0` の最初の k を `r13` に入れる (anchor 相当)。見つからなければ `r13` は最後に読んだ 0。
- `0x12e68a0(base, index, r8b)` の戻りを `dil` に入れる (F と呼ぶ)。F の中身は §3 で書く。
- `0x12e8210(base, index, s, &first, &last)` で区間 `[first, last]` を得る (0x12e7fe9)。`0x12e8210` は次のとおり (確定): `first = last = index` と置く (0x12e8210・0x12e8213)。`s == 0` なら返す (0x12e8216〜0x12e821b)。`s ≠ 0` なら `first` から下へ、`last` から上へ、`+0x3e ≠ 0` が連続する限り区間を広げる (0x12e8216〜0x12e825a)。`+0x3e` は『選択済み』の印 (推定。`0x12e8120` の選択判定と同じ byte)。
- 区間ループ (0x12e7ff3〜0x12e8105・k = 1..500 で各 k について):
  - F が偽 (0x12e7ff6 の枝が無い側): `r13 ≠ 0` なら `+0xd4` の検査 (0x12e7ffc)。`r13 == 0` のとき `+0xd6 ← +0x3c` (0x12e8001〜0x12e8019)。
  - `+0xd5 ≠ 0` かつ `k ≠ index` の track は `+0x3c` を変えない (0x12e802c〜0x12e8039)。それ以外は、区間の内側 (`first ≤ k ≤ last`、0x12e803d〜0x12e8056) なら `+0x3c ← 1`、外側なら `+0x3c ← 0` (0x12e8058〜0x12e8063)。
  - `+0xd4 ← (k == index)` (0x12e8068〜0x12e8083)。
  - F が真 (0x12e8085〜0x12e80ed): `+0x3c ← bl | (cfg+0x49e ≠ 0 ? +0xd6 : 1)` (0x12e80a5〜0x12e80e8)。`cfg = [[[0x15e13b8]] + 0xd98]` は REPORT_PY105 §5 のとおり。
  - 最後に `+0xd4 ← 0` (0x12e80f5)。
- `+0xd4`・`+0xd6` の意味 (推定): `+0xd4` は『直前に操作した track の印』。`+0xd6` は『solo 状態の退避先』。どちらも名前は推定で、PY-105 §5 の推定と同じ。
- **cfg+0x49e (未確定)**: 0x12e80b6 で読む bool。bool の意味は未確定 (PY-105 §5 と同じ。cfg のクラスが決まらないため)。

## 2. 0x12e3a60 (select mode 1 の後処理・確定)

`0x12e3a60(base, index)` (rbx = base、edx = index):

1. `+0xd8 == 3` の枝 (0x12e3a73〜0x12e3b2e):
   - `src = dword [base + index*0x114 + 0xe0]` (0x12e3a85)。
   - `0 ≤ src ≤ dword [*(G1) + 0x10] - 1` (0x12e3aa0〜0x12e3aac) のとき、`0x11e84a0(src)` と `0xfe8bb0(*(G1), src)` を呼ぶ (0x12e3ac3・0x12e3add)。戻り object の `+0x258` (dword) を `id` とする。
   - `byte [*(G2)+0xa9] ≠ 0` かつ `1 ≤ id ≤ 500` のとき `0x128f9e0(*(G2), id, r8b)` (0x12e3ae2〜0x12e3b2e)。
2. `+0xd8 == 1` の枝 (0x12e3b41〜0x12e3b8e): `byte [*(G2)+0xa9] ≠ 0` かつ `1 ≤ +0xdc ≤ 500` のとき `0x128f9e0(*(G2), +0xdc, r8b)`。
3. `r8b` は 0x12e3b9c の 1 byte (`.text`、値 0x01)。実行時に書き換わらない定数 (PY-105 §6 と同じ)。

G1 = `[0x15e2218]` は `TChanList` (PY-105 §6・確定)。`0x128f9e0` の名前と G2 の型は未確定 (PY-105 §6 のとおり)。

## 3. 0x12e68a0 (F の中身・確定の範囲)

`0x12e68a0(base, index, r8b)`:
- `0x12e8210(base, index, r8b, ...)` で区間 `[first, last]` を得る (0x12e68c8)。`edi = 1` で始める (0x12e68b0)。
- 区間内の各 k で `+0x3c ≠ 0` を調べ、1 つでも 0 があれば `edi = 0` にする (0x12e68de〜0x12e68f6)。
- 区間の外側を含めた k = 1..500 の走査 (0x12e6901〜0x12e6947): `+0x3c ≠ 0` かつ `+0xd5 == 0` の track があれば `edi = 0` (0x12e6925〜0x12e693a)。

まとめ (読みの確定): F = 『区間内の全 track が `+0x3c ≠ 0`、かつ区間外に `+0x3c ≠ 0` で `+0xd5 == 0` の track が無い』。名前 (solo 判定など) は推定。

## 4. 0x666780 の呼出し元 (0xd56770・確定・所属は未確定)

`0xd56770(rcx = self = rbx)`:
- `self+0x60 ← -2` (0xd56778)。`[[[rip+0x88e009]]+8]` の vtbl `+0x98` の呼出し (0xd56794) が真なら `self+0x60 ← 0` (0xd5679e)。
- `self+0x18` (index) が 1..500 の範囲内 (0xd567a6〜0xd567b6) のとき:
  - `self+0x20 == -1` の枝 (0xd567d7〜): `0x12e1a20()` (track 表の取得・PY-105 §1) を `rcx` に、`edx = self+0x18`、`r8 = 0`、`r9b = (self+0x28 == 1)` で `0x12e7f80` を呼ぶ (0xd567dc〜0xd567ee)。
  - その後 `mov ecx, 0x26`・`xor edx, edx`・`call 0xbd68e0` (0xd567f3〜0xd567fa)。よって `0xbd68e0(0x26, 0)` が 0x12e7f80 の直後に 1 件出る。
- `0xd56770` の所属 VMT は逆引きで見つからず未確定 (PY-105 §7 と同じ)。
