# PY-257 REPORT (#3816): r8d 判定の未確認ビットの分岐先の作用

親: #2034 (PY-65)。前段: `REPORT_PY41.md` の「r8d 判定箇所」節 (ビットの意味は未確定)・`analysis/py53_dispatch.py` (逆アセンブル)・`analysis/py60_objdump_check.py` (objdump 照合)。既知類型との関係: 該当なし (逆アセンブルの読解のみ・lift 作業ではない)。issue が参照する「PY-65 節」は `REPORT_PY41.md` に無いため、本 REPORT を新設した。

## 1. 結論

- 判定箇所は **173 件** (`test eax, M` の全件・`mov eax, [rbp+0x5c0]` の直後)。PY-53 の「174 件」は `and dword ptr [rbp+0x5c0], 0xffffffdf` の 1 件を含む数。
- 対象 13 マスク (0x4・0x10・0x14・0x10000・0x8000・0x8a1・0x240・0x200・0x1000・0x2000・0x2800・0x4000・0x3c0) は **63 判定・126 側**。
- **作用の範囲は「無条件 jmp を辿った経路」**。条件 jcc は分岐先を辿らない (§2)。対象 126 側のうち **111 側は未追跡の jcc を持つ**。jcc の先の本体は §5 の未解決 (#2034)。
- 早期 exit (0x104cc72 への到達): 対象 126 側のうち **13 側** (7 判定: 0x1046dc4・0x1046dde・0x1046e23 (立ち)・0x1046e50・0x1046ef6・0x1046f2e・0x104710b)。全件が末尾の `jmp 0x104cc72` (0x10471f9) で入る。未追跡の jcc で 0x104cc72 へ向かう辺は 0 件。
- 共通後半 0x104caae に入る (終端が tail) 側は **113 側** (入口が 0x104caae 自身の側 11 件を含む)。
- 経路上に `[rbp+0x5b8]` への書込みを持つ側は **19 側** (10 判定)。残る 94 側は経路上に書込みなし (入口前の値を引き継ぐ)。
- 共通後半で `[rbp+0x5b8]` を読む命令は 2 件 (0x104caec・0x104cc65)。0x104caec の読み値は 113 側すべてについて §4 に記録した。
- 検算: objdump (intel) 照合で 344 行の mismatch 0 (§2・§6)。負の対照 (je の変位を 1 つ変えた入力) で mismatch 1・exit 1。

## 2. 測定条件・定義

- 素材: `$ARTIFACTS_DIR/fl-win64.tar.zst` から `block00031_PE.bin` (22,227,016 B) を展開 (`tar --zstd -xf $ARTIFACTS_DIR/fl-win64.tar.zst -C work/py65 --wildcards '*block00031_PE.bin'`・2.7 秒)。`work/` は gitignore。
- 逆アセンブル: `python3 analysis/py53_dispatch.py work/py65/extracted/block00031_PE.bin work/py65/py53` → `fn=4664 dispatch=13 r8d_tests=174`。
- 測定 commit: `1327cb6db` (解析器 `analysis/py257_r8d_bits.py` を含む merge commit。解析コードは `8ef42e74e` の無条件 jmp 版を改名したもので、`8ef42e74e` の時点の出力と一致)。`git diff 1327cb6db HEAD -- tools/python/analysis` の出力は 0 行 (以後の commit は本 REPORT と DOC_MAP のみ)。
- 判定の定義: 判定箇所の直後の分岐で両側の入口を決める。`je` は分岐先が落ち側 (M の全ビットが 0)・fall-through が立ち側。`jne` はその逆。判定 173 件のうち 171 件は `je`/`jne` (342 側)。残る 2 件 (`0x104a821` の `test eax, 0xffffffdd`・`0x104a835` の `test eax, 2`) は直後が `setne` で jcc ではないため、側を定義せず表に入れない。
- **作用の経路 (本 REPORT の定義)**: 入口から fall-through と無条件 jmp を辿る。止める所は 0x104caae (tail)・0x104cc72 (exit)・ret・関数外・経路の再訪 (loop)。**条件 jcc は分岐先を辿らない**。分岐先は TSV の `edges` に、未追跡の本数は `open_jcc` に記録する。
- 書込み = 先頭オペランドがメモリの命令 (cmp・test・push・call・jmp・lea・ucomi* を除く)。呼出し = call 命令 (呼出し先の中は見ない)。
- 「早期 exit」= 経路が 0x104cc72 に到達すること。REPORT_PY41.md の PY-60 節の訂正: 0x104cc72 は通常経路 (0x104cc6b → 0x104cc71 nop → 0x104cc72) と共有する後始末ブロックで、-1 専用の早期 exit ではない。本 REPORT の「早期 exit」は、jmp で 0x104cc72 へ入る経路を指す。PY-60 節が挙げる 0x104cc72 へ飛ぶ 9 件のうち、対象 126 側の追跡経路に現れるのは 0x10471f9 (jmp) の 1 件のみ。残る 8 件 (0x1046d8d・0x10474b9・0x104846a・0x104847b・0x10495f6・0x1049621・0x104a7ba・0x104a7d0) は対象の追跡経路の外。
- 検算: capstone (`analysis/py64_branch_regions.py` の `load` を流用) と objdump (`-M intel`・`-b binary`) の結果を、判定箇所 (VA・mask・jcc・分岐先) と各側の (入口・命令数・終端・終端へ入った命令・書込み・呼出し・辺・早期 exit・未追跡 jcc・読み値の決まり) で行ごと照合した。
- 負の対照: 0x1046dc9 の `je` (`74 3a`) の変位を +1 した入力 (`work/py65/neg/neg.bin`・fn.txt は元のまま) で `mismatch=1`・exit 1。
