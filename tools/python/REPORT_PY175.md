# PY-175 (#3252): 効果関数 `0x1046a30` の n 書込み先 (key 下位 16bit の枝・負の key 入口・flags `0x3e9`)

既知類型との関係: 該当なし (lift 作業ではない。PE の逆アセ解析)。親: #3213 (PY-170)。前段: `tools/python/REPORT_PY72.md` の「追加解析 (PY-77 / #2576)」節 受入 C (`0x1051c90`・`0xf824b0` の確定) と `tools/python/REPORT_PY73_APPENDIX_2547.md` (振り分け表)。

## 結論

- 確定: `0x1046a30(key=ecx, n=edx, flags=r8d)` の先頭から `0x104770c` までの範囲では n (`[rbp+0x5b8]`) を一度も読まない (逆アセ全文の `[rbp+0x5b8]` 参照は 84 行目の退避以降、600 行目が最初)。key 下位 16bit の 0・2・3・8 の枝は、flags `0x3e9` で n の格納先が決まった (下表)。
- 確定: 0x1046ed3・0x10471c1 の「key 下位 16bit == 8」の判定は `[rbp+0x51c]` を 0 にするだけで、n の格納には関係しない。`[rbp+0x51c]` は 0x1046efd の事象記録 (`[global]=key`・`[global+4]=値`) の要否にだけ効く。
- 確定: 負の key の入口 (`0x1047424`〜`0x1047497`) の分岐。`0x104aa87` (`[0x70000000, 0x7fffffff]` と `[0x80000000, 0xf0000000)`) の 0x1f00 枝 (`0x104ab38`) は n を格納せず、符号だけを書く。
- 未確定 (子 issue へ): 負の key の残りの枝、key 1・5・6・7・9 以降の枝、flags `0x3e9` の戻り値 eax、`0x1050f90` の本体。
