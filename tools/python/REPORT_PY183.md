# PY-183 (#3288): 0x1051720 の 10519c6 枝 (表示枝) の副作用の PE 確定

親: #3253 (PY-176)。前段: `tools/python/REPORT_PY176.md` §5・§6 (枝の命令列と呼出し順は確定済み)。前段 (key の定義): `tools/python/REPORT_PY72.md` 節 2 (`key = ((chan+0x794)&0xffff)<<16 | 4`)。
既知類型との関係: 該当なし (lift 作業ではない。PE の逆アセンブルによる解析)。

## 結論 (PE 実測で確定した範囲)

- 10519c6 枝 (cur と new の表示枝) 自身が書く store は rbp/rsp 相対の局所だけ (§1。probe で mov 命令を照合)。呼出し先で読んだ範囲の直接のグローバル store は 3 箇所: UI の文字列 `0x16bd1a0`・フラグ `0x16bd1a8` (`0x11f1a20`)、フラグ表 `0x16b6dcc+0xa` (`0xbd68e0`、通知)、`0x16bb13c` (`0x104f580` 末尾の `0x1050540`)。仮想呼出し先と `0x104f2d0` の副作用は未追跡 (§2・§9)。表示文字列の全文と組立て順は確定 (§1・§2)。
- 表示文字列は `<パラメータ名> is waiting for pickup: <cur 表示>  < <new 表示>` (cur < new) または `… <new 表示>  > <cur 表示>` (cur ≥ new)。cur 表示・new 表示は cents 値 `+N cent(s)` (§3)。cur と new の表示文字列が等しいときは new を `%.2f%` のパーセントに置き換える (§1)。
- `0x104f580` の production 枝 (key 下位 16bit = 4) を確定 (§2)。パラメータ名は `[desc+0xe4]` の文字列を §2.2 の 3 段で変換した値 (変換は確定。`desc` の値は [PY-328] #4449 の範囲)。
- `0x104d2b0` の production 枝 (下位 16bit = 4) を確定 (§3)。書式エンジン `0x43dde0` の `%d` の出力規則は確定 (PY-192・§3)。`%.2f` の丸めは未確定 (子 [PY-311])。
- `0x414e70` は wstring の内容比較 (等しければ 0) と確定 (§4)。
- 表示先 (`0x16bd1a0`・`0x16bd1a8`) を確定。`0xbd68e0(0xa, 0)` は「フラグ表の byte が立っているときだけ `0x666780` へイベントを投げる」と確定。投げた先 `0x666780` の本体と、フラグを立てる側は未読 (子 [PY-193])。
- **受入 5 (未初期化 `ac`)**: 0xff 経路 (`0x1051909`) で `[rbp+0xac]` は読まれる (`0x105193c`)。`f82a10` が `bb = 0xff` のまま `ac` を書かずに返る経路 (`0xf82a49` の不一致など) があり、その経路では `ac` は実行時のスタックの残存値。10519c6 枝に入るか (`sign == ac`) は、この残存値で決まる。残存値は静的に確定できない (§6)。

## 2. 0x104f580 (production 枝: 低位 4) (受入 1)

引数: `rcx` = out1 (`[rbp+0x180]` に保存)、`edx` = key (`[rbp+0x34]`)、`r8` = out2 (`[rbp+0x38]`)、`r9b` = flag (`[rbp+0x198]`)。プロローグで out1・out2 を `0x412d60` で空にする。

分岐 (追跡した経路だけ):

1. `key < 0x10000000` (`0x104f714`〜`0x104f719`) なら chan 経路 (`0x104f75a`)。`chan = key>>16`。
   - `chan < G.count` (`[[0x15e2218]+0x10]`): `obj = G.items[chan]` (`[[…]+8]`)。`obj.vtbl[+0x68](obj, &[rbp+0x148], 0)` で名前を取り、out2 ← 名前 ‖ `" - "` (`0x1050650`) (`0x104f7a9`)。

   - その他: `0x1050532` (末尾へ)。
2. 低位 16bit = 4 は `0x104f842` の `je 0x104fa17` で分岐。

### 2.1 型判定 0x40fe90 (PY-324 #4400・#4436 で確定)

- `0x40fe90(obj, T)`: `obj == null` なら false。そうでなければ `x = *obj` (obj の vtable) を `0x410010(x, T)` に渡し、その戻り al を返す (`0x40fe99`〜`0x40fea3`)。
- `0x410010(x, T)`: `x == T` なら true。そうでなければ `p = [x-0x78]` (基底への参照)、`p == 0` なら false、`x = [p]` (基底の vtable) として繰り返す (`0x410013`〜`0x410024`)。**`obj` のクラスが `T` と同じか、その基底鎖に `T` を持つ**ときだけ true になる (継承鎖の is-a 判定)。
- `T` は `[rip-0x6cdf1]` (`0x104fa1a`) のセル `0xfe2c30` の内容で、そのセル自体は `.text` (読取専用) に置かれた定数 `0xfe2cf8` である。`T` の基底鎖 (vtable 列) は `0xfe2cf8 → 0xfe2978 → 0x12b05b0 → 0x12b0358 → 0x132e150 → 0x401a38` の 5 段で、末尾の `[0x401a38-0x78] == 0` で偽になる (各段の `[x-0x78]` = 基底参照は `0xfe28b0`・`0x12b04e8`・`0x12b0290`・`0x132e088`・`0x401970`・`0`)。
- 確定したこと: 判定は「`obj` の型が `T` (またはその派生) か」の is-a 判定。`T` の型名 (RTTI の TypeDescriptor) は本 run では読めなかった (MSVC RTTI の辿り方で名前が取れず未確定)。
- 未確定: 実行時に `obj` がどのクラスの vtable を持つか (`G.items[chan]`・Omni オブジェクトの実体)。よって「この key で true になるか」は静的に決まらない。`[obj+0x160] == 5` と合わせた「Time stretch」表示の実発火条件も実行時値次第。
- 検証: `analysis/flapi/pe_py183_probe.py` に `typecheck_checks()` 11 件を追加 (96 件 PASS・`summary: OK`)。ネガティブコントロール: VA `0x410018` の先頭バイト `0x48` (REX.W) を `0x90` に置換した複製で FAIL (`FAIL 0x410010 の基底の辿り方 …`・`1 FAIL`・終了 1)。

### 2.2 desc 経路 0x104f2d0 の out1 (PY-191 #3377)

- `0x104f2d0(ctx, desc)`: `desc == 0` なら out1 (`[ctx+0x180]`) を空にする (`0x104f346`→`0x412d60`)。`desc != 0` なら `S = [desc+0xe4]` (wstring) に次の 3 段を順に適用し、結果を out1 にコピーする (`0x104f302`〜`0x104f33f`)。呼出し元は `0x104fa5f` (`desc = [[0x15e2200]+0x940]`)。
  1. `0x605020(out, S)`: S の最初の `|` (`0x60507c`) より後ろを取る。`|` が無ければ S 全体 (`0x605045`)。検索は `0x44b430` → `0x4150d0` (開始位置 1 始まり・戻り値は 1 始まりの位置、0 は未発見。`0x414f20` の 1 始まり引数と整合)。切出しは `0x414ec0`。
  2. `0x662d20` → `0x662c30`: 先頭が `^` (0x5e) の間ループする。2 文字目で分岐する。`^.` (`.`) は 3 文字除去して flags |= 2。`^?`・`^^` は 2 文字除去し、残りに `^` があればその位置までを除去 (無ければ何もしない) し、flags は変えない。`^_`・`` ^` `` は同じ検索・除去をしたうえで flags |= 1。`^a` を含むそれ以外は 2 文字除去のみ (検索しない)。2 文字目の判定は `c - 0x5e` (c は 2 文字目) を `cmp eax,3; jae 0x662cd2` で見るため、検索に入るのは `^`・`_`・`` ` `` の 3 種だけ (`a` = 0x61 は範囲外で、`0x662cd2` の既定分岐に入る)。flags (`[rbp+0x2c]`) は `0x662d20` 側で捨てる。
  3. `0x439c90`: 両端の 16bit 文字が `<= 0x20` のものを削る (trim)。
- 確定したこと: out1 = trim(マーカー除去(`S` の最初の `|` より後ろ))。**値は S (実行時の desc の内容) に依存し、PE 上の定数としては決まらない。** 決まるのは変換の形。
- 検証: `analysis/flapi/pe_py183_probe.py` の `desc_text_checks()` (17 件、全 PASS。`a` が範囲外であることの check を含む)。読みは逆アセンブルによるもので、関数は実行していない。

## 3. 0x104d2b0 (production 枝: 低位 4) と cents 表示 (受入 2)

- `0x104d2b0(out, key, v)`: プロローグで out を空にし、低位 16bit = 4 (`0x104d3ae` の `je 0x104d55b`) で `0x104d55b`: `0x11f12c0(out, v)` (`0x104d562`)。`jmp 0x104dcb6`。
- 末尾 `0x104dcb6`: `out` が空でなければ `0x104dd76` で return。`0x11f12c0` は非空を返すので、`0x104d000` (の検索) は production では通らない (コードからの判定。実行はしていない)。
- `0x11f12c0(out, v)` (`0x11f12c0`〜`0x11f1370`):
  - 単位: `|v| == 1` なら `"cent"` (`0x11f13dc`)、それ以外は `"cents"` (`0x11f13c4`) (`0x11f12e3`〜`0x11f12f1`。`|v|` は `(v ^ s) − s`)。
  - 書式: `0x43dd60(out, "%d %s" (0x11f13f4), &{v, 0, unit, tag 0x11}, 1)` (`0x11f134d`。第 4 引数 r9=1)。
  - 符号: `v > 0` のとき out ← `"+" (0x11f140c) ‖ out` (`0x11f1357`〜`0x11f136b`)。`v == 0` は `+` なし (`jle`)。
- 書式エンジン `0x43dde0` の `%d` (PY-192 で確定): `0x43e240` の変換指定子 `D` (0x44) が `0x43eaa7` で `0x43a7e0` (符号付き整数) を呼ぶ。`0x43a7e0` は `|v|` と符号 flag (`setl`) を `0x43a3f0` に渡し、`0x43a3f0` は負のとき先頭に `-` (0x2d) を書き、桁数を `|v|` の範囲比較 (10 進 1〜10 桁) で決める。`+` は呼出し側 `0x11f12c0` が付ける。`%s` (cents / cent) は単位文字列のまま。
- 結果: `+12 cents`・`+1 cent`・`0 cents`・`-N cents` (確定。probe の `format_checks` で呼出し辺と分岐を照合)。

## 4. 0x414e70 (wstring 比較) (受入 2)

- `0x414e70(a, b)`: 両ポインタが同じなら 0。どちらか null なら -1 (両方 null は同じ扱いで 0)。両方非 null なら長さ (`[p−4]`) が違えば -1、同じなら 2·len バイトを比べ、一致で 0、不一致で -1。
- 10519c6 枝では `cur_t` と `new_t` の一致判定だけに使う。一致 ⇔ 同じ cents 値 (表示が一対一なら)。

## 5. 表示先・通知 (受入 4)
