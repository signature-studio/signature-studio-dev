親: #3253 (PY-176)。前段: `tools/python/REPORT_PY176.md` §5・§6 (枝の命令列と呼出し順は確定済み)。前段 (key の定義): `tools/python/REPORT_PY72.md` 節 2 (`key = ((chan+0x794)&0xffff)<<16 | 4`)。

## 結論 (PE 実測で確定した範囲)

- 10519c6 枝 (cur と new の表示枝) は、**G・V・K・chan への書込みをしない**。書くのは UI の文字列 `0x16bd1a0`・フラグ `0x16bd1a8` と、通知 `0xbd68e0(0xa, 0)` だけ。表示文字列の全文と組立て順は確定 (§1・§2)。
- 表示文字列は `<パラメータ名> is waiting for pickup: <cur 表示>  < <new 表示>` (cur < new) または `… <new 表示>  > <cur 表示>` (cur ≥ new)。cur 表示・new 表示は cents 値 `+N cent(s)` (§3)。cur と new の表示文字列が等しいときは new を `%.2f%` のパーセントに置き換える (§1)。
- `0x104f580` の production 枝 (key 下位 16bit = 4) を確定 (§2)。パラメータ名 (`[desc+0xe4]` の先) は未確定 (子 [PY-190])。
- `0x104d2b0` の production 枝 (下位 16bit = 4) を確定 (§3)。書式エンジン `0x43dde0` の `%d`・`%.2f` の出力規則は未読 (子 [PY-191])。
- `0x414e70` は wstring の内容比較 (等しければ 0) と確定 (§4)。
- 表示先 (`0x16bd1a0`・`0x16bd1a8`) を確定。`0xbd68e0(0xa, 0)` は「フラグ表の byte が立っているときだけ `0x666780` へイベントを投げる」と確定。投げた先 `0x666780` の本体と、フラグを立てる側は未読 (子 [PY-192])。
- **受入 5 (未初期化 `ac`)**: 0xff 経路 (`0x1051909`) で `[rbp+0xac]` は読まれる (`0x105193c`)。その経路で `ac` は書かれず、値は実行時のスタックの残存値。10519c6 枝に入るか (`sign == ac`) は、この残存値で決まる。静的には確定できない (§5)。

`0x414da0` は 5 要素の引数ブロック (`r8`・`r9`・stack[0x20]・[0x28]・[0x30] = `[rbp+0x50]`〜`[rbp+0x70]` の配列) を `0x4144a0(out, 5, block)` に渡す。`0x4144a0` は `block[0..4]` を順に連結して out に入れる (null は長さ 0。自己参照は `r13` で検出して一時領域を取る)。連結の仕様は `0x414c70` (2 要素) と同じ。

## 2. 0x104f580 (production 枝: 低位 4) (受入 1)

引数: `rcx` = out1 (`[rbp+0x180]` に保存)、`edx` = key (`[rbp+0x34]`)、`r8` = out2 (`[rbp+0x38]`)、`r9b` = flag (`[rbp+0x198]`)。プロローグで out1・out2 を `0x412d60` で空にする。

分岐 (追跡した経路だけ):

1. `key < 0x10000000` (`0x104f714`〜`0x104f719`) なら chan 経路 (`0x104f75a`)。`chan = key>>16`。
   - `chan < G.count` (`[[0x15e2218]+0x10]`): `obj = G.items[chan]` (`[[…]+8]`)。`obj.vtbl[+0x68](obj, &[rbp+0x148], 0)` で名前を取り、out2 ← 名前 ‖ `" - "` (`0x1050650`) (`0x104f7a9`)。
   - `chan ≥ G.count` かつ `chan == 0xfff` (`0x104f7b6`): out2 ← `"Omni - "` (`0x1050664`) (`0x104f7d4`・`0x104f7e4`)。
   - その他: `0x1050532` (末尾へ)。
2. 低位 16bit = 4 は `0x104f842` の `je 0x104fa17` で分岐。
   - `0x40fe90(obj, 型記述子)` が真 (型判定) かつ `[obj+0x160] == 5` (`0x104fa2a`): out1 ← `"Time stretch"` (`0x1050680`) (`0x104fa41`)。
   - それ以外: `0x104f2d0(ctx, [[global]+0x940])`。`desc != 0` なら out1 ← `f(desc+0xe4)` (`0x605020` → `0x662d20` → `0x439c90` の連鎖。未読)、`desc == 0` なら out1 を空にする。
3. 末尾 `0x1050532`: `flag = (out1 が空)` を `[0x16bb13c]` に書き (`0x1050540`)、`flag` なら out1 ← `"Unknown event" (0x1050978) ‖ " (#" (0x10509a0) ‖ 0x43aa10(key, 8) ‖ ")" (0x10509b4)` (`0x414da0`)。その後 `0x414bb0(out2, out1)` で out2 ← out2 ‖ out1 (追記)。戻り値は out1 (`0x10505e6`)。

確定した効果:

- 0x1051720 が読むのは out1 (`[rbp+0x78]`) だけ。out2 (チャネル名 + " - " + パラメータ名) は 0x1051720 では使われず空にされる (`0x1051b52`)。**表示はチャネル名を含まない**。
- `0x104f580` 自身は G・V・K・chan を書かない (書込みは out1・out2 と一時領域のみ)。
- `0x43aa10(key, 8)` の書式は未読。「8 桁の数値表示」は引数からの推定 (子 [PY-191])。

未確定: `0x104f2d0` の desc (`[[global]+0x940]`) の値と `f(desc+0xe4)` の中身 (子 [PY-190])。

## 3. 0x104d2b0 (production 枝: 低位 4) と cents 表示 (受入 2)

- `0x104d2b0(out, key, v)`: プロローグで out を空にし、低位 16bit = 4 (`0x104d3ae` の `je 0x104d55b`) で `0x104d55b`: `0x11f12c0(out, v)` (`0x104d562`)。`jmp 0x104dcb6`。
- 末尾 `0x104dcb6`: `out` が空でなければ `0x104dd76` で return。`0x11f12c0` は非空を返すので、`0x104d000` (の検索) は production では通らない (コードからの判定。実行はしていない)。
- `0x11f12c0(out, v)` (`0x11f12c0`〜`0x11f1370`):
  - 単位: `|v| == 1` なら `"cent"` (`0x11f13dc`)、それ以外は `"cents"` (`0x11f13c4`) (`0x11f12e3`〜`0x11f12f1`。`|v|` は `(v ^ s) − s`)。
  - 書式: `0x43dd60(out, "%d %s" (0x11f13f4), &{v, 0, unit, tag 0x11}, 1)` (`0x11f134d`。第 4 引数 r9=1)。
  - 符号: `v > 0` のとき out ← `"+" (0x11f140c) ‖ out` (`0x11f1357`〜`0x11f136b`)。`v == 0` は `+` なし (`jle`)。
- 結果 (コードからの組立て。書式エンジン未読のため数字の桁の出方は推定): `+12 cents`・`+1 cent`・`0 cents`・負は `-N cents` (推定)。

## 4. 0x414e70 (wstring 比較) (受入 2)

- `0x414e70(a, b)`: 両ポインタが同じなら 0。どちらか null なら -1 (両方 null は同じ扱いで 0)。両方非 null なら長さ (`[p−4]`) が違えば -1、同じなら 2·len バイトを比べ、一致で 0、不一致で -1。
- 10519c6 枝では `cur_t` と `new_t` の一致判定だけに使う。一致 ⇔ 同じ cents 値 (表示が一対一なら)。

## 6. 受入 5: 0xff 経路の未初期化 `ac` の判定

経路 (listing の順):

1. `0x1051842` `cmp byte [bb], 0` → `0x1051849` `jne 0x1051909` (`bb = 0xff` は f82a10 が書いていない)。
2. `0x1051909` `cmp byte [bb], 2` → `jne 0x1051916`。`0x1051916`〜`0x105193c` で `rax = sign(cur−new)`。
3. `0x105193c` `movsxd rcx, dword ptr [rbp+0xac]` ← **ac を読む**。`0x1051946` `setne al` (al = sign ≠ ac)。
4. `0x105194b` `je 0x10519c6` (sign == ac なら 10519c6 枝へ)。

検証 (probe):

- `0x1051909`〜`0x105193c` の範囲に `rbp+0xac` を参照する命令は無い (probe の `stores == []`)。
- `ac` への書込みは `0x1051857`・`0x10518b2` の 2 箇所だけで、どちらも `bb == 0` の経路 (`0x105184f`〜)。
- f82a10 が未発見のとき `ac` を書かないことは REPORT_PY176 §2 の記載に依る (本 run では f82a10 の本体を再照合していない)。

判定: **PE の経路上で読まれる (未初期化の読出し)**。値はスタックフレームの残存値で、静的には決まらない。影響: 0xff 経路で残存値が `sign(cur−new)` と一致すると 10519c6 枝 (表示・通知)、不一致だと `0x105196a` (`bb = 2` で `0xf82c20` に保存) に進む。どちらになるかは実行時の残存値次第。f82a10 が未発見になる発生条件 (表 T0 と未発見経路の到達性) は既存の子 [PY-182] (#3287) の対象。
