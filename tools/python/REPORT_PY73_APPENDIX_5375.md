# PY-5375 付録: 0x41c160 を持つ .text 内ポインタ表の全箇所と参照元 (#5625)

親: #5458 (PY-5345)。前段: #4138 の停止報告。本付録は `tools/python/REPORT_PY73.md` の上限 250 行に入らないため別置きした (内容は削除していない)。
再現: `FL_WIN64_DIR=<展開先> python3 analysis/flapi/pe_abs_table_xref.py 41c160` (展開は `tools/python/analysis/flapi/pe_disasm.py` と同じ `block00031_PE.bin`)。

## 1. 結論

- 0x41c160 の絶対 VA 8 バイト値は PE の `.text` 内に **73 箇所** ある。issue #5625 本文は「10 箇所」と書くが列挙は 11 VA で、その 11 VA は全て本表に含まれる (本表は 73 箇所の全件)。
- 73 箇所は **すべて .text 内の連続ポインタ run の中にある** (run は 73 本、長さは 1〜34 slot、長さ 15 が 60 本。`.pdata` の関数内ではなく、関数間のデータ領域)。idx 9 (= 0x41c160) が 72 本、idx 0 が 1 本 (`0x40379f` の 1 スロット run・別扱い、下の §3)。
- **どの run も RIP 相対・絶対 disp で読まれていない** (参照 0 件)。直接の `call` / `jmp 0x41c160` も 0 件。`.data`・`.rdata` 等の他 section からも、run の先頭 VA を 8 バイトで持つ箇所は 0 件。
- したがって **0x41c160 の上位 (誰が表を引くか・誰が 0x41c160 を呼ぶか) は PE 静的解析では確定できない**。FLEngine 起動前段への到達は確定していない。
- emulator の初期化起点 (関数 VA) は **未確定 (理由: 上記の参照元 0 件)**。推測の初期値では実装していない。

## 2. 0x41c160 の中身

- `0x41c160`: `sub rsp,0x28; call 0x40f960; mov dword ptr [rax+8],1; add rsp,0x28; ret` (`pe_disasm.py` 実測)。
- 呼ぶ先 `0x40f960` は X の工場 (#5458 の停止報告で確定済み)。

## 4. 追加確認 (2 回目の run)

前回は `.pdata` の関数内しか逆アセンブルしていなかったため、関数外の領域を含めて次を確認した。

- **`.text` 全体の線形走査** (`analysis/flapi/pe_abs_linear_5375.py`): 命令単位で 5,022,467 命令を読み、解読不能 161,366 バイトは 1 バイトずつ飛ばした。73 run に対する RIP 相対の参照は **1 件** (`0x9e1a18` の `xor byte ptr [rip+0x9e], dl`)、即値一致は 12 件。
  - `0x9e1a18` は `0x9e1a00` 付近の 0 埋め領域を命令として誤デコードしたもので、実参照ではない (`pe_disasm.py` で確認)。
  - 即値一致 12 件 (`0x4910f4`・`0x50b2a5` 等) は `jcc`・`loopne`・`call` のオペランドの偶然の一致。`0x4910f4` は前後が `add byte ptr [rdx], al` の連続で、データ領域の誤デコード。
  - 結論: 線形走査でも 73 run を読む実参照は見つからない。
- **ファイル全体の 4 バイト RVA (`0x1c160`) の一致**: 2 件。`.text` の `0x4aa55c` は `call 0x4c66c0` の rel32 の偶然の一致。`.pdata` の 1 件は `0x41c160` 自身の関数エントリ (begin = 0x41c160) で、参照元ではない。
- **`.reloc` の確認**: 73 スロットすべてに `IMAGE_REL_BASED_DIR64` の再配置が付いている。絶対 VA を持つ値であることは確かだが、これだけでは表として使われる証拠にはならない。表を読む参照が見つからないため、上位の確定は依然できない。

測定: `FL_WIN64_DIR=<展開先> python3 analysis/flapi/pe_abs_linear_5375.py` real 79.5 s (user 79.4 s)、実行前 load average 0.37。
