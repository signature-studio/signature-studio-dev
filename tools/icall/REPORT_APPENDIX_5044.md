## 1. 結論

- 受入 2 の**直接**の呼出し先 `180cbcd90`・`180cb9890` は、関数本体 (先頭から `ret` まで) に `r13` を書く命令が 0 件。
- 間接の呼出し `180cbba21` (`call [rax+0x8]`)・`180cbba36` (`call [rax+0x10]`) の具象型は**静的に未特定**。`r13` の保存は未確認。受入 2 は部分達成。
- 受入 3 (`180703b7c` の届き判定) は、間接呼出しの `r13` 保存に依るため、本付録では結論を書かない。

## 2. 判定の方法

`tools/icall/r13_callee_check.sh` で行う。

1. `objdump -d -M intel` の全量を `tools/icall/work/core64.dsm` に出力 (初回のみ、約 5 秒で完了)。
2. 関数本体は、開始アドレス行から `ret` の直後に `int3` パディングが来るまでを切り出す。
3. 本体の命令のうち、宛先オペランドが `r13`/`r13d` のもの、または `xchg` で `r13` を入れ替えるものを数える。

検証: 3 関数とも、切り出し行の先頭が開始アドレス、末尾が `ret` になることを確認した (`180cbb930` 76 行・`180cbcd90` 192 行・`180cb9890` 56 行)。切り出しの誤りで 0 件になったことがあったため (`.text` 見出し行を境界と誤認した)、修正後の値で再判定した。
