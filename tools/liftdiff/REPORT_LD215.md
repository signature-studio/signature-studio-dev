# liftdiff LD-215 (#4429) — 併存 20 関数の戻りレジスタを、分岐を越えた呼出し元・呼出し先の経路で判定

> 親 #4379 (LD-212) の子。前段 [`REPORT_LD212.md`](REPORT_LD212.md) は窓 24 命令の線形読みで止まった。
> 結論: **受入条件は未達**。判定の『候補』が一意に決まったのは 20 関数のうち 3 件 (`6ed480`・`40c420`・`40f210`)。型は未確定で、`targets/m11.json` の `ret_override` は変えていない。

## 1. 結論

- 判定器 `tests/ld215_retprop.py` は、呼出し元を分岐の両方向に辿り (`call`・間接 `jmp` で打ち切り)、rax / rdx / xmm0 の『読まれる』『上書き』『ret まで素通し (pass)』『未確定 (unknown)』を分類する。呼出し先は ret に至る全経路で must-def / may-def を求める。
- 判定基準 (§3 の表の列から機械的に当てはめる): 呼出し元の rax / rdx / xmm0 のいずれにも『未確定』が 0 件 (呼出し元の全経路が決まる)、かつ呼出し先の must-def と呼出し元の『読』の積集合がちょうど 1 レジスタ → 戻り『候補』が一意。
- 該当は 3 件。`6ed480` (xmm0。3 呼出し元で `ucomisd` 等に読まれる)、`40c420` (xmm0。読まれるのは 1 件・`addsd`)、`40f210` (xmm0。読まれるのは 2 件・`mulsd`)。3 件とも rax / rdx は読まれない。
- ただし 3 件とも型 (double か float か) は確定していない。`6ed480` の呼出し元が読むのは `ucomisd` (比較) で、戻り型の証拠として弱い。LD-158 は同関数を『rax 書換えあり・区別不能』で対象外にしており、この判定はそれを覆す根拠として不十分。`40c420`・`40f210` の xmm0 の読みは演算命令で、呼出し前の値の再利用が混じる可能性がある (§4)。3 件とも `ret_override` には入れない。
- 残り 17 関数は『未確定 (unknown)』が残るか、呼出し先の経路が間接分岐で打ち切られ must-def を出せなかった。窓を越えても確定しない。

## 2. 方法 (再現)

- 入力: `FL_WIN64_DIR` の PE `extracted/block00031_PE.bin` (fl-win64 素材を `$RUNNER_TEMP/fl-win64` に展開)。
- スクリプト: `tests/ld215_retprop.py` (初版 `2216acab7`。`cand` 列に未確定 0 件の条件を入れたのは測定 commit `dbfe14b1b`)。
  - 呼出し元: E8 rel32 走査で call 命令を集め、target が一致したものだけを数える (LD-212 と同じ)。call 直後から最大 `--budget` (既定 400) 命令・経路数で打ち切る。`xor r,r` は読みから除外する。
  - 呼出し先: entry から全経路を辿り、ret 到達時点で書かれたレジスタの積 (must) と和 (may) を取る。呼出し先の `call` は clobber のみ (定義とは数えない)。
- 実行: `FL_WIN64_DIR=$RUNNER_TEMP/fl-win64 python3 tools/liftdiff/tests/ld215_retprop.py <PE> --tsv work/ld215_probe.tsv`。
- `cand` 列 (TSV の `cand`・出力の『候補』行) は §1 の判定基準どおり、rax / rdx / xmm0 に『未確定』が 1 件でもある関数は空にする。判定器の出力で候補が出るのは `6ed480`・`40c420`・`40f210` の 3 件で、§1 と一致する。
- 所要時間: 実測 **0.30 秒** (wall。素材 fl-win64 の PE・同じ素材で実行した 1 回目の値)。

- 列の意味: 読 = 戻り後に読まれた (候補)、上 = 戻り後に上書きされた、素 = ret まで素通し、未 = 窓・経路で決まらず。

- 呼出し先の must-def に rax・rdx・xmm0 の 3 つすべてが入るのは `4421d0`・`5b0970`・`8e6660` の 3 関数だけ。must は呼出し先の ret 経路すべてで書かれるレジスタで、呼出し元の利用 (読 / 上 / 素 / 未) とは独立に出る。そのため §1 の判定では must と『読』の積を取った。

## 4. 前段 (LD-212) との差

- 前段の窓 24 命令の読みでは「rax / rdx 読 0 件」。本 PR の経路追跡でも同じ。窓を広げただけでは戻りは決まらない。
- 追加で分かったのは、xmm0 が多くの関数で呼出し元の**比較・演算命令** (ucomisd・addsd・mulsd・divsd・cvtsd2ss) に読まれること。これは戻り値の利用と読めるが、呼出し前の値の再利用も混じるため、型を確定する証拠にはならない。
