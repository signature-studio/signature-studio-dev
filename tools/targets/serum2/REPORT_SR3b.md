# Serum 2 OSS 版同定 (SR-3b / #867, 親 #71)

本ファイルは `tools/targets/serum2/REPORT.md` §11.5 の未解決 (版未確定) の詳細。結論は REPORT §11.5 に 1 行で置く。

- 既知類型との関係: 該当なし (静的な版同定。silent miscompile 類型は未触)。
- 入力: `Serum2_win64.vst3` sha256 `501e7bb3…5283` (19,236,864 B)。
- 検証起点: commit `99b87bc2` (ws-867 worktree, クリーン HEAD)。
- 再現: `bash tools/targets/serum2/scripts/sr3b_run.sh` (`work/Serum2_win64.vst3` が必要。無ければ `sr3_run.sh` で展開)。

## 1. 結論

| ライブラリ | 判定 | 根拠 (実測) |

## 2. muParser の突合 (実測)

NUL 終端で単独に現れる upstream 文字列リテラルの数 (`out/sr3b_version.txt`)。

| upstream | リテラル | バイナリに単独一致 | 不一致 |
|---|---:|---:|---:|
| v2.2.5 | 39 | 36 | 3 |
| v2.3.2 | 42 | 34 | 8 |
| v2.3.4 | 42 | 34 | 8 |
| v2.1.0 / 2.2.0 / 2.2.4 / 2.2.6 / 2.3.0 / 2.3.1 / 2.3.3 | — | 取得不可 (404) | — |

判別文言 (NUL 終端単独の出現数):
- `...must be preceeded by a closing bracket.` (typo `preceeded`): **1** (v2.2.5 に存在)
- `...must be preceded by a closing bracket.` (正しい綴り, v2.3.x): **0**
- `Function result is a string.` (v2.2.5 のみ): **1**
- `Expression too long.` / `Identifier too long.` / `Strings must only be used as function arguments!` (v2.3.x のみ): **0 / 0 / 0**

2.2.5 の判別文言が一致し、2.3.x の判別文言は 0 件。よって版は 2.3.x ではなく 2.2.x 系と読める。ただし 2.2.0〜2.2.4 は取得できていないため、2.2.5 と確定はできない (推定)。

## 3. 窓外 muParser 6 関数の帰属 (未解決)

§11.3 の窓外 6 関数 (`0x1809e3240` `0x1809eb7b0` `0x1809ef030` `0x1809ef7b0` `0x180a0a3e0` `0x180a0f3f0`) は、組込み関数名の登録側かを確かめた。
- 組込み関数名 (`acos` `sinh` `sqrt` `log10` `ceil` 等 21 種) を NUL 終端単独で `.rdata` に持つ。
- `.text` の RIP 相対 lea で名前を参照する命令は **0 件** (95,268 の RIP 相対命令を走査)。
- 8 バイト絶対ポインタで名前を参照する箇所も **0 件**。
- よって、名前の参照は静的に追えない (実行時に組立てる表と推定)。帰属は**確定できず**、窓の拡張も本 run では行わない。
- **訂正 (SR-3d #867, 測定 commit `530ac84b`)**: 上の「RIP lea 0 件」は誤りだった。同じ 95,268 件の走査で、名前 5 件への RIP lea は計 7 件 (6 関数の内部)。名前は実行時組立てではなく、名前表 (0x180fae640) と各関数の lea で参照される。詳細は `REPORT_SR3d.md` §2・§4。

## 4. 検証記録

- 所要: `sr3b_run.sh` 28.7 s (実測・1 回目, 4 core, load average 0.73)。`sr3b_run.sh` 単独の再実行 29.0 s (ws-867, HEAD `99b87bc2`)。
- 出力 `out/sr3b_version.txt` は決定的 (同一入力で再実行し同内容)。
- 判別の両側確認: 2.2.5 のみにある文言 (`preceeded`・`Function result is a string.`) と 2.3.x のみにある文言 (`preceded` 系・`Expression too long.` 系) を別々に数え、一方のみ 1 件・他方 0 件となることを確認 (§2)。
- 窓外 6 関数の名前参照走査 (§3) は一回限りの調査で、スクリプトはコミットしていない (結果のみ記録)。
- 範囲外: 実機・wasm での挙動、upstream の再ビルド品との関数単位の一致、版 2.2.0〜2.2.4 の完全突合。
- 既知の限界: `sr3b_version.py` の muParser 判定は文字列単独一致のみ。版ごとに文言が変わる箇所以外は判別力が無い。
