# Serum 2 SR-21: `.pdata` 外コード 20,467 ブロックの分類と cut 方針 (#1444 / 親 #71)

親: `REPORT.md` §11.3・§11.5 (`.pdata` 外 19,115 ブロックの関数性が未確定)。
再現: `PY=python3 bash scripts/sr3_run.sh` → `bash scripts/sr21_run.sh` (`work/` 要・素材 `plugins-serum2` の Install exe 要)。
既知類型との関係 (`docs/DEFECTS.md`): 該当なし (lift 前の静的分類。silent miscompile 類型は未触)。

## 0. 結論 (先出し)

- `.pdata` 外の 20,467 ブロック / 318,398 B を **7 区分**に分けた (§1)。合計は 20,467 ブロック・318,398 B で既存 `sr3_gap_blocks.tsv` と一致。
- **関数入口と判定できるのは 1,352 ブロック / 101,257 B** (直接 call 参照 844、rip 相対参照のみ 464、jmp/jcc のみ 44)。REPORT §11.3 の「1,352 / 101,257」と一致。
  - うち **direct call で確認できる 844 ブロック (86,060 B)** が最も強い入口根拠。
- **未確定は 19,115 ブロック / 217,141 B** (= 318,398 − 101,257。区分は §1 の `table_ptr` 3,928 / `ptr_single` 80 / `unref` 15,102 / `data` 5 の計 19,115 ブロック、B 数は 83,235 + 1,267 + 132,498 + 141 = 217,141)。関数性は未確定のまま残す。
- **cut 表 (`out/sr3_cut_table.tsv`) とは矛盾しない**。gap ブロックと cut 関数の重なりは 0 件 (§3)。ただし cut 窓内に隣接する gap ブロック 217 件 (2,280 B) は cut 表に入っていない (§4 未解決)。
- **lift 方針** (§5): cut 表は変えない。入口候補は「強 / 弱 / 未確定」の 3 段で扱い、未確定は lift 入口に使わない。

## 1. 分類 (`out/sr21_summary.txt`・`out/sr21_classify.tsv`)

判定は**上から順に最初に当たったもの**。区分の意味は確度順。

| 区分 | ブロック | B | ret 含むブロック | 判定の根拠 | 確度 |
|---|---:|---:|---:|---|---|
| `entry_call` | 844 | 86,060 | 680 | 直接 `call` (E8) の標的 | 入口 (強) |
| `entry_rip` | 464 | 11,800 | 395 | `lea`/`mov` の rip 相対参照のみ (データ読みも含むため弱い) | 入口? (弱) |
| `branch_only` | 44 | 3,397 | 36 | `jmp`/`jcc` の標的のみ (分割ブロック・尾部呼出の候補) | 分割候補 |
| `table_ptr` | 3,928 | 83,235 | 3,314 | 参照なし。`.rdata`/`.data` の 8 バイト連続値 (≥2 連続) がブロック先頭を指す (vtable・関数ポインタ表型) | 間接呼出の候補 |
| `ptr_single` | 80 | 1,267 | 10 | 参照なし。ポインタ 1 件のみ | 弱 |
| `unref` | 15,102 | 132,498 | 21 | 参照なし・ポインタなし・clean decode | **未確定** |
| `data` | 5 | 141 | 1 | 参照なし・clean decode 失敗 (末尾が途切れる) | データ候補 |
| **合計** | **20,467** | **318,398** | **4,457** | | |

- 補足: `.pdata` 外の **パディング** (0xCC/0x90/0x00 の連続) は「ブロック」ではないため上表に含めない。`sr3_gaps.py` の実測で **145,350 B** (`REPORT.md` §11.3 と同じ)。パディングを除いた 463,748 − 145,350 = 318,398 B が上表の合計。
- 数え方: ブロックは `sr3_gaps.py` の定義 (0xCC/0x90/0x00 以外の連続域を、`0xCC 0xCC` で切った単位)。**関数境界ではない**ため 1 ブロックに複数関数や末尾データが入りうる。サイズは関数サイズの上限。

## 2. 入口判定の根拠 (`entry_call` / `entry_rip` / `branch_only`)

- `entry_call` 844 件の参照元数 (call + rip の合計) の分布: 1 件 331 / 2 件 150 / 3 件 58 / 4 件 49 / 5 件以上 256。**844 件すべてに `.pdata` 内の参照元がある** (`from_pdata` > 0 が 844/844)。gap 内からの参照だけの `entry_call` は 0 件。
- `entry_rip` 464 件のうち、参照元が `.pdata` 内なのは 461、gap のみは 3。rip 相対は定数・データ読みと区別できないため、**単独では入口と言えない** (弱)。
- `branch_only` 44 件: 参照元は `.pdata` 内 12 / gap 内 32。gap 内の参照元は分割ブロック同士の連結と推定 (**推定**)。入口ではなく分割候補として扱う。
- 参照は capstone による命令単位の抽出 (`sr21_classify.py` が `sr3_index.py` の `refs` を使用)。

## 3. 独立検算 (`scripts/sr21_verify.py`・`out/sr21_verify.txt`)

capstone を使わず、生バイト列から判定した (別アルゴリズム)。

| 区分 | blocks | E8 (call) 標的 | E9/0F8x (jmp/jcc) 標的 | 8B ポインタ 標的 |
|---|---:|---:|---:|---:|
| `entry_call` | 844 | 844 | 93 | 66 |
| `entry_rip` | 464 | 0 | 0 | 8 |
| `branch_only` | 44 | 0 | 44 | 5 |
| `unref` | 15,102 | 7 | 5 | 0 |
| `data` | 5 | 0 | 0 | 5 |
| 全体 | 20,467 | 851 | 142 | 4,092 |

- 生バイト走査は命令境界に揃えていないため、capstone の 844 より多い (851) のは想定内 (命令内の E8 を拾う偽陽性)。
- `unref` の call 標的 7 件 / jmp 標的 5 件は、この偽陽性と推定する (命令境界の確認は未実施・**推定**)。
- `table_ptr` 3,928 件はすべて連続ポインタ列の中にある (単独 80 件を除く)。**vtable かどうかは RTTI 照合を未実施** (推定)。
- **ネガティブコントロール**: 各ブロック先頭を +1 バイトずらすと、call 標的 1 件 (本来 851)・ポインタ 0 件 (本来 4,092)。判定が偶然一致ではないことを示す。
- **cut 表との重なり**: gap ブロックと cut 関数 (1,414 区間に統合) の重なりは **0 件**。cut 区間全体を +0x2000 ずらすと 469 件重なる (ネガティブコントロール)。
- `.pdata` 内から始まるブロックは 0 件 (分類の前提が成立)。

## 5. lift 対象の方針 (本 issue の決定事項・提案)

1. **cut 表 (`out/sr3_cut_table.tsv`) は変更しない**。SR-21 の分類は cut 表の外側だけに適用し、重なりは 0 件。
2. **入口候補は 3 段で扱う** (lift 入口の追加は動的トレース #75 の到達確認後):
   - 強: `entry_call` 844 件 (86,060 B) → lift 入口候補に加える。
   - 弱: `entry_rip` 464 件 (11,800 B)・`branch_only` 44 件 (3,397 B) → 候補。到達確認が無い限り入口にしない。
   - 未確定: `table_ptr` 3,928 件 (83,235 B)・`ptr_single` 80 件・`unref` 15,102 件 (132,498 B)・`data` 5 件 → **lift 入口に使わない**。
3. **未確定ブロックが動的に到達した場合は fail-closed** (未知の入口に入ったら trap として止める)。黙って誤った code を実行しない。この挙動は lift 側の実装 (#75 の範囲) で確認する。
4. 「入口候補 (強)」の 844 件は、`.pdata` 33,791 件とは別の追加入口。wasm 再ビルドの除外範囲は変えない (`out/sr3_cut_table.tsv` のまま)。
