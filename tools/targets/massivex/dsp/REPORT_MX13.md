### 2.2 収束しない原因の扱い (確認事項)

- 閉包 507,258 入口のうち、.pdata の関数先頭 (begin) は **13,246 件 (2.6%)** で、残り **494,012 件 (97.4%) は .pdata 外の番地**。
- 閉包の .pdata 関数カバレッジは 13,246 / 186,960 = **7.08%** (`closure_pct_of_pdata`)。旧 REPORT の「入口数 146,761 = .pdata 関数数の 78.5%」は、入口 (.pdata 外を含む) と関数数を比べた誤った比較だったため撤回する。
- つまり「収束しない」の実体は、call/jmp 先として到達した .pdata 外の番地 (データ・関数途中) が入口として増え続けること。本 PR の実装は code/data を区別せず、入口の判定を .pdata begin で絞っていない。これが受入 1 の未達の中心。
- 到達バイト増加: round 1 の 208,409 から round 7 の 10,461,947 まで増え、その後減少。収束は到達の減衰による。
- 間接 jmp 未解決 (累計 3,107) は、閉包の拡大を抑える根拠になっていない (間接 jmp の先を追わないため、その先の code は閉包に入らない)。
